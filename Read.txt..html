1. Назначение глобальных уникальных адресов IPv6 (IPv6 GUA Assignment)Ручная настройка: На роутере глобальный уникальный адрес IPv6 (GUA) настраивается вручную с помощью команды интерфейса ipv6 address ipv6-address/prefix-length.Автоматическая настройка: При выборе автоматического получения адреса хост пытается самостоятельно запросить и настроить параметры IPv6 на интерфейсе.Локальный адрес (LLA): IPv6-адрес для связи со смежными узлами (Link-Local Address) создается хостом автоматически при загрузке, как только сетевой интерфейс активируется.Роль роутера: По умолчанию роутер с поддержкой IPv6 периодически рассылает информацию, позволяя хостам динамически создавать или получать конфигурацию.Управляющие сообщения (RA): Решение о том, как именно хост получит адрес GUA, определяется настройками в сообщении Router Advertisement (RA) протокола ICMPv6. Сообщение RA содержит три ключевых флага:Флаг A (Address Autoconfiguration): Указывает использовать SLAAC для создания IPv6 GUA.Флаг O (Other Configuration): Указывает запросить дополнительные параметры (например, DNS) у stateless DHCPv6 сервера.Флаг M (Managed Address Configuration): Указывает использовать stateful DHCPv6 сервер для получения IPv6 GUA.2. Метод SLAAC (Stateless Address Autoconfiguration)Суть метода: SLAAC позволяет хостам создавать собственные уникальные глобальные уникальные адреса IPv6 без обращения к DHCPv6 серверу. SLAAC является «бесстатусным» (stateless).Принцип работы: Метод использует ICMPv6 сообщения RA. SLAAC может работать как самостоятельно, так и в паре с DHCPv6.Активация на роутере: Чтобы роутер начал отправлять RA-сообщения, нужно включить маршрутизацию глобальной командой ipv6 unicast-routing. Проверить статус можно командой show ipv6 interface.Значение флагов по умолчанию: Когда включена базовая маршрутизация IPv6, интерфейсы с настроенным GUA начинают рассылать RA-сообщения, где флаг A установлен в 1, а флаги O и M установлены в 0.Флаг $A = 1$ говорит клиенту сформировать адрес на основе префикса из RA.Флаги $O = 0$ и $M = 0$ предписывают использовать информацию исключительно из сообщения RA.Частота отправки: Роутер отправляет RA-сообщения каждые 200 секунд, а также принудительно отвечает на запрос хоста (Router Solicitation, RS).Генерация идентификатора интерфейса (Interface ID): Получив 64-битный префикс от роутера, хост генерирует оставшиеся 64 бита интерфейсного идентификатора одним из двух способов:Случайным образом (randomly generated).С помощью метода EUI-64.Проверка уникальности (DAD): Процесс DAD (Duplicate Address Detection) гарантирует уникальность созданного адреса в сети. DAD реализуется через ICMPv6 сообщения NS (Neighbor Solicitation) с использованием специального multicast-адреса (solicited-node multicast address), который дублирует последние 24 бита IPv6-адреса хоста.3. Протокол DHCPv6 (Stateless и Stateful)Порты: Обмен сообщениями между клиентом и сервером DHCPv6 идет поверх протокола UDP: сервер слушает порт 546, а клиент отправляет с порта 547.Stateless DHCPv6 (Безстатусный режим):Хост получает адрес с помощью SLAAC (из RA-сообщения), но за дополнительными параметрами (например, адресами DNS-серверов) обращается к DHCPv6 серверу.Сервер не хранит никакой информации о состоянии клиента (stateless).Настраивается на интерфейсе роутера командой ipv6 nd other-config-flag (переводит флаг O в значение 1).Stateful DHCPv6 (Статусный режим):Сообщение RA указывает клиенту получить абсолютно все сетевые настройки (кроме шлюза по умолчанию) от DHCPv6 сервера. Шлюзом по умолчанию становится локальный адрес роутера (LLA), отправившего RA.Сервер хранит состояние распределенных адресов (stateful).Настраивается на интерфейсе роутера командой ipv6 nd managed-config-flag (переводит флаг M в значение 1).4. Настройка DHCPv6 сервера и ретранслятора (Configure DHCPv6 Server)Роли роутера Cisco IOS: Роутер может выступать в трех ролях:DHCPv6 сервер (раздает настройки).DHCPv6 клиент (сам получает конфигурацию от другого сервера).DHCPv6 ретранслятор (перенаправляет запросы).Проверка работы: Для мониторинга и отладки используются команды:show ipv6 dhcp pool — проверка пулов DHCPv6.show ipv6 dhcp binding — просмотр привязок выданных адресов.DHCPv6 Relay Agent (Ретранслятор):Если DHCPv6 сервер находится в другой подсети, роутер настраивается как ретранслятор.Команда настройки на интерфейсе, смотрящем на клиентов: ipv6 dhcp relay destination ipv6-address [interface-type interface-number]. Указывается IP-адрес сервера и исходный интерфейс (нужен, если адрес следующего хода — LLA).Для проверки ретранслятора применяются команды show ipv6 dhcp interface и show ipv6 dhcp binding.
