1. Концепции DHCPv4 (DHCPv4 Concepts) Что это такое: Сервер DHCPv4 динамически назначает (или «сдает в аренду» — lease) IPv4-адреса клиентским устройствам из общего пула адресов. Аренда выдается на ограниченное время, определенное сервером, либо до тех пор, пока клиенту нужен адрес. Это избавляет от ручной настройки и гарантирует, что отключенные или ушедшие из сети устройства не будут занимать нужные IP-адреса. Процесс получения аренды (4 шага при загрузке): Когда устройство подключается к сети, оно запускает процесс из четырех шагов (аббревиатура DORA): DHCPDISCOVER — клиент ищет доступные серверы DHCP в сети (широковещательный запрос). DHCPOFFER — сервер отвечает и предлагает клиенту свободный IP-адрес. DHCPREQUEST — клиент официально запрашивает предложенный адрес. DHCPACK — сервер подтверждает аренду, и IP закрепляется за клиентом. Продление аренды (2 шага): До истечения срока аренды клиент обновляет её с сервером в два шага: DHCPREQUEST (запрос на продление) и DHCPACK (подтверждение). 2. Настройка DHCPv4-сервера на Cisco IOS (Configure a Cisco IOS DHCPv4 Server) Основные шаги настройки: Обычный маршрутизатор Cisco IOS можно превратить в DHCP-сервер. Для этого нужно: Исключить зарезервированные статические IP-адреса (команда ip dhcp excluded-address). Создать пул адресов и задать ему имя (ip dhcp pool <имя>). Настроить параметры пула (сеть, маску, шлюз по умолчанию, DNS). Служба DHCP по умолчанию: Она включена в Cisco IOS автоматически. Чтобы её выключить, используется глобальная команда no service dhcp. Проблема раздельных сетей (Реле / DHCP Relay): В крупных корпоративных сетях DHCP-серверы часто находятся в центральном сегменте, а клиенты — в других подсетях. Широковещательные запросы от клиентов не проходят через маршрутизатор сами по себе. Решение — ip helper-address: Чтобы маршрутизатор перенаправлял запросы клиентов на удаленный сервер, на интерфейсе смотрящем в сторону клиентов настраивается команда ip helper-address <адрес_сервера>. Какие службы пересылает хелпер по умолчанию: Команда ip helper-address автоматически перенаправляет 8 важных UDP-портов: Порт 37 (Time — время) Порт 49 (TACACS) Порт 53 (DNS) Порт 67 и 68 (DHCP / BOOTP сервер и клиент) Порт 69 (TFTP) Порт 137 и 138 (NetBIOS Name Service и Datagram Service) Команды для проверки: show running-config | section dhcp (проверка конфигурации) show ip dhcp binding (активные арендованные адреса) show ip dhcp server statistics (статистика работы сервера) ipconfig /release и ipconfig /renew (на ПК для сброса и обновления IP) 3. Настройка DHCPv4-клиента (Configure a DHCPv4 Client) Настройка на интерфейсе маршрутизатора: Чтобы интерфейс маршрутизатора сам получал настройки от провайдера (например, при подключении кабельного или DSL-модема), используется команда режима конфигурации интерфейса: ip address dhcp. Домашние роутеры: Большинство домашних маршрутизаторов «из коробки» настроены на получение параметров от провайдера автоматически. В настройках тип подключения обычно выставлен как Automatic Configuration - DHCP, что заставляет устройство запрашивать IP-адрес у оборудования провайдера (ISP).
