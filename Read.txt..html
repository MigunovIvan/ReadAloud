Раздел первый. Особенности и характеристики протокола OSPF. Open Shortest Path First, или сокращённо OSPF — это протокол маршрутизации по состоянию канала, который был разработан как альтернатива дистанционно-векторному протоколу RIP. OSPF обладает значительными преимуществами перед RIP, поскольку обеспечивает более быструю сходимость сети и легко масштабируется для работы в гораздо более крупных сетевых инфраструктурах. Для обеспечения масштабируемости OSPF использует концепцию областей. Под каналом или линком в этом протоколе понимается интерфейс маршрутизатора. Также каналом считается сегмент сети, соединяющий два маршрутизатора, или тупиковая сеть, например локальная сеть Ethernet, подключённая только к одному маршрутизатору. Вся информация о состоянии канала включает в себя префикс сети, длину этого префикса и стоимость маршрута. Все протоколы маршрутизации используют специальные сообщения для обмена информацией о путях. Эти сообщения помогают формировать структуры данных, которые затем обрабатываются с помощью алгоритма маршрутизации. Маршрутизаторы, работающие под управлением OSPF, обмениваются сообщениями для передачи маршрутной информации, используя пять типов пакетов. Первый тип — это пакет приветствия Hello. Второй тип — пакет описания базы данных DBD. Третий тип — пакет запроса состояния канала LSR. Четвёртый тип — пакет обновления состояния канала LSU. И пятый тип — пакет подтверждения состояния канала LSAck. Сообщения OSPF используются для создания и поддержания трёх основных баз данных. Первая — база данных смежности, на основе которой строится таблица соседей. Вторая — база данных состояния каналов LSDB, которая формирует таблицу топологии. Третья — база данных пересылки, из которой создаётся сама таблица маршрутизации. Маршрутизатор строит таблицу топологии, используя результаты вычислений, основанных на алгоритме кратчайшего пути Дейкстры, который также называют алгоритмом SPF. Работа алгоритма SPF базируется на совокупной стоимости пути до места назначения. Именно метрика стоимости используется в OSPF для определения наилучшего маршрута до конечной сети. Чтобы поддерживать актуальную информацию о маршрутах и достичь состояния полной сходимости сети, маршрутизаторы OSPF выполняют стандартный процесс маршрутизации по состоянию канала, состоящий из пяти последовательных шагов. Шаг первый: установление отношений смежности с соседями. Шаг второй: обмен объявлениями о состоянии каналов. Шаг третий: построение базы данных состояния каналов. Шаг четвёртый: запуск и выполнение алгоритма SPF. Шаг пятый: выбор наилучшего маршрута. При настройке однообластного OSPF для обозначения области можно использовать любой номер, однако лучшей практикой считается использование нулевой области, то есть области ноль. Однообластной OSPF отлично подходит для небольших сетей с малым количеством маршрутизаторов. В многообластном OSPF один большой домен маршрутизации можно разделить на несколько областей меньшего размера для поддержки иерархической маршрутизации. При этом маршрутизация между областями продолжает работать, а ресурсоёмкие операции, такие как пересчёт базы данных топологии, изолируются и выполняются только внутри своей области. Для обмена префиксами протокола IPv6 используется версия OSPFv3, которая является полным аналогом OSPFv2 для сетей IPv4. Стоит помнить, что в терминологии IPv6 сетевой адрес называется префиксом, а маска подсети называется длиной префикса. Раздел второй. Пакеты протокола OSPF. Для установления и поддержания отношений смежности с соседями, а также для обмена обновлениями маршрутизации, OSPF использует пять уже упомянутых пакетов состояния канала: Hello, DBD, LSR, LSU и LSAck. Пакеты обновления LSU также применяются для пересылки оперативных изменений в сети, например, при отключении или включении какого-либо канала. Пакеты приветствия Hello выполняют три ключевые задачи. Во-первых, они обнаруживают соседей OSPF и устанавливают с ними отношения смежности. Во-вторых, они передают параметры, по которым два маршрутизатора должны прийти к согласию, чтобы стать соседями. В-третьих, они используются для выборов выделенного маршрутизатора DR и резервного выделенного маршрутизатора BDR в сетях с множественным доступом, таких как Ethernet. На прямых соединениях типа точка-точка выборы DR и BDR не требуются. Важными полями внутри пакета Hello являются: тип пакета, идентификатор маршрутизатора Router ID, идентификатор области Area ID, маска сети, интервал приветствия Hello, приоритет маршрутизатора, интервал простоя Dead, адреса DR и BDR, а также список известных соседей. Раздел третий. Принцип работы OSPF. Когда маршрутизатор с настроенным OSPF впервые подключается к сети, он пытается выполнить четыре основные задачи: создать смежность с соседями, обменяться информацией о маршрутизации, вычислить наилучшие пути и достичь состояния сходимости. Для достижения этой цели OSPF последовательно проходит через семь состояний. Первое состояние: Down, или отключено. Второе состояние: Init, или инициализация. Третье состояние: Two-Way, или двусторонняя связь. Четвёртое состояние: ExStart, или начало обмена. Пятое состояние: Exchange, или непосредственный обмен. Шестое состояние: Loading, или загрузка. Седьмое состояние: Full, или полная смежность. Когда протокол OSPF включается на интерфейсе, маршрутизатор должен определить, есть ли на этом канале другой сосед OSPF. Для этого он рассылает пакет Hello, содержащий его собственный идентификатор маршрутизатора, через все интерфейсы с активным OSPF. Пакет Hello отправляется на зарезервированный многоадресный адрес IPv4 для всех маршрутизаторов OSPF — 224.0.0.5. Обрабатывать такие пакеты будут только маршрутизаторы с запущенным OSPFv2. Когда соседний маршрутизатор получает пакет Hello с идентификатором отправителя, которого ещё нет в его списке соседей, принимающий маршрутизатор пытается установить смежность с инициатором. После достижения состояния двусторонней связи Two-Way маршрутизаторы переходят к этапам синхронизации баз данных. Этот процесс состоит из трёх шагов. Шаг первый: выбор первого маршрутизатора, который начнёт обмен. Шаг второй: обмен пакетами описания базы данных DBD. Шаг третий: отправка запроса состояния канала LSR для получения недостающих деталей. Сети с множественным доступом могут создавать для OSPF две серьёзные проблемы, связанные с лавинной рассылкой объявлений о состоянии каналов LSA. Первая проблема — это создание слишком большого количества отношений смежности между всеми устройствами. Вторая проблема — чрезмерная лавинная рассылка самих объявлений LSA. Резкое увеличение числа маршрутизаторов в такой сети приводит к лавинообразному росту количества передаваемых пакетов, что серьёзно нагружает сеть и снижает эффективность работы OSPF. Если бы каждый маршрутизатор в сети с множественным доступом был обязан рассылать и подтверждать все полученные объявления каждому другому маршрутизатору, сетевой трафик стал бы совершенно хаотичным. Именно поэтому в таких сетях необходимы выборы выделенного маршрутизатора DR и резервного выделенного маршрутизатора BDR. В сетях с множественным доступом OSPF выбирает один маршрутизатор на роль DR, который становится единой центральной точкой сбора и распределения всех отправляемых и получаемых объявлений LSA. Одновременно с этим выбирается резервный маршрутизатор BDR, который мгновенно возьмёт на себя эти функции в случае сбоя основного выделенного маршрутизатора.
