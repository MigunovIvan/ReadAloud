Модуль 14.6.1: Итоги модуля «Концепции маршрутизации» В этом материале собраны ключевые темы по работе маршрутизаторов, таблицам маршрутизации и принципам выбора пути. 1. Определение пути (Path Determination) Главные задачи роутера: Определение лучшего пути для пересылки пакетов на основе таблицы маршрутизации и отправка пакетов к месту назначения. Понятие «longest match» (самое длинное совпадение): Лучший путь в таблице маршрутизации выбирается по наибольшему количеству совпадающих бит слева в IP-адресе назначения. Непосредственно подключенные сети (Directly Connected Networks): Сети, которые настраиваются на активных интерфейсах роутера. Сеть добавляется в таблицу маршрутизации автоматически, когда интерфейсу присваиваются IP-адрес с маской (префиксом), и он переводится в состояние активен (up and up). Способы изучения удаленных сетей: Статические маршруты: добавляются вручную администратором. Динамические протоколы маршрутизации: маршруты добавляются автоматически с помощью протоколов вроде EIGRP и OSPF. 2. Пересылка пакетов (Packet Forwarding) Возможные действия с пакетом: после определения пути роутер может переслать пакет в непосредственно подключенную сеть, передать его следующему роутеру (next-hop) или отбросить. Главная обязанность: инкапсуляция пакетов в кадр канального уровня (data link frame) нужного типа для исходящего интерфейса. Механизмы коммутации пакетов: роутеры поддерживают process switching (процессорную коммутацию), fast switching (быструю коммутацию) и CEF (Cisco Express Forwarding). Пошаговый процесс пересылки пакетов: Кадр канального уровня с инкапсулированным IP-пакетом поступает на входящий интерфейс (ingress interface). Роутер проверяет IP-адрес назначения в заголовке пакета и сверяется с таблицей маршрутизации. Роутер находит префикс с самым длинным совпадением (longest match). Роутер инкапсулирует пакет в кадр канального уровня и отправляет через исходящий интерфейс (egress interface) — напрямую узлу или следующему роутеру. Если подходящая запись в таблице отсутствует, пакет сбрасывается. 3. Обзор базовой конфигурации роутера (Basic Router Configuration Review) Основные команды настройки и проверки: show ip route, show ip interface, show ip interface brief и show running-config. Фильтрация вывода команд: чтобы сократить объем текста на экране, после команды ставится символ вертикальной черты (|), после чего указывается параметр и выражение для фильтрации: section — показывает весь раздел, который начинается с указанного выражения. include — выводит только те строки, которые содержат указанное выражение. exclude — исключает из вывода строки, содержащие указанное выражение. begin — начинает вывод с той строки, которая совпадает с указанным выражением. 4. Таблица маршрутизации (IP Routing Table) Что содержит таблица: список известных сетей (префиксов и длин префиксов), полученных от напрямую подключенных сетей, статических маршрутов и динамических протоколов. Буквенные коды маршрутов: L — адрес, назначенный интерфейсу самого роутера (Local). Позволяет роутеру понять, что пакет предназначен именно ему. C — непосредственно подключенная сеть (Connected). S — статический маршрут (Static). O — маршрут, изученный динамически через протокол OSPF. * (звездочка) — маршрут является кандидатом на роль маршрута по умолчанию (default route). Ключевые принципы: Каждый роутер принимает решение самостоятельно на основе собственной таблицы, и таблицы разных роутеров могут отличаться. Информация о пути туда не гарантирует наличие обратного маршрута. Записи включают: источник маршрута, сеть назначения, административное расстояние (AD), метрику, следующий прыжок (next-hop), таймстамп и исходящий интерфейс. Маршрут по умолчанию (Default Route): используется, когда в таблице нет точного совпадения для IP-адреса назначения. Записывается как IPv4 0.0.0.0/0 или IPv6 ::/0. Может быть статическим или динамическим. Структура таблиц: IPv4 таблицы сохраняют классовую структуру с отступами (levels of indentation), в то время как IPv6 таблицы её не используют. Административное расстояние (Administrative Distance — AD): определяет «надежность» источника маршрута. Чем ниже значение AD, тем более доверенным считается источник. 5. Статическая и динамическая маршрутизация (Static and Dynamic Routing) Когда применяются статические маршруты: В качестве маршрута по умолчанию для пересылки трафика к провайдеру. Для маршрутов вне домена маршрутизации, которые не изучаются динамическими протоколами. Когда администратор хочет явно задать путь к конкретной сети. Для маршрутизации между тупиковыми сетями (stub networks). Когда применяются динамические протоколы: В сетях, состоящих более чем из нескольких роутеров. Когда изменения топологии требуют автоматического поиска обходных путей. Для масштабируемости сети при её росте. Классификация протоколов: IGP (Interior Gateway Protocols): обмен информацией внутри одного административного домена (примеры: OSPF, EIGRP). EGP (Exterior Gateway Protocols): обмен информацией между разными организациями. Единственный представитель — BGP, который используется провайдерами в интернете. Алгоритмы маршрутизации: делятся на distance vector (дистанционно-векторные), link-state (состояния канала) и path vector (вектора пути). Компоненты динамических протоколов: структуры данных, служебные сообщения и алгоритмы. Выбор лучшего пути и метрика: лучший путь выбирается на основе наименьшей метрики (количественного показателя расстояния до сети). Балансировка нагрузки (Equal Cost Load Balancing): если у роутера есть несколько путей к цели с одинаковой стоимостью (метрикой), он передает пакеты по всем этим путям одновременно.
