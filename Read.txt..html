Модуль 10.5: Атаки на локальные сети (LAN Attacks) Введение Данный раздел посвящен изучению различных типов атак, направленных на коммутаторы (свитчи) и уровень передачи данных (Layer 2) модели OSI, а также методам их предотвращения. 1. 10.5.2 Атаки типа "Побег из VLAN" (VLAN Hopping Attacks) Суть атаки: Позволяет трафику из одной виртуальной сети (VLAN) передаваться в другую VLAN без участия маршрутизатора (роутера). Как это работает: Злоумышленник настраивает свое устройство (хост) так, чтобы оно имитировало работу коммутатора. Это делается для того, чтобы воспользоваться функцией авто-транкинга (автоматического образования магистральных каналов), которая по умолчанию включена на большинстве портов свитча. Технические детали: Хакер подделывает сигналы 802.1Q и проприетарные сигналы Cisco DTP (Dynamic Trunking Protocol), чтобы принудительно установить транковое (магистральное) соединение с подключенным коммутатором. Если атака удается, злоумышленник получает доступ ко всем VLAN на данном свитче и может свободно отправлять и принимать трафик в любой из них. Защита от атак на VLAN: Отключите транкинговый режим на всех портах доступа (access ports). Отключите авто-транкинг на магистральных линиях, чтобы транки настраивались только вручную. Убедитесь, что выделенный Native VLAN используется исключительно для магистральных каналов. 2. 10.5.3 Атака с двойным тегированием VLAN (VLAN Double-Tagging Attack) Суть атаки: В определенных ситуациях злоумышленник внедряет скрытый тег стандартов 802.1Q внутрь фрейма, который уже содержит один тег 802.1Q. Этот второй тег заставляет коммутатор отправить пакет в ту VLAN, которую исходный внешний тег не указывал. Как это работает (по шагам): Злоумышленник отправляет кадр с двумя тегами. Внешний заголовок содержит тег VLAN атакующего, который совпадает с Native VLAN магистрального порта (например, VLAN 10). Внутренний тег принадлежит целевой сети (например, VLAN 20). Первый коммутатор снимает внешний тег (поскольку он совпадает с Native VLAN) и пересылает кадр дальше по транку. Второй коммутатор видит внутренний тег (VLAN 20) и доставляет пакет целевому хосту в заблокированной для атакующего сети. Особенности: Такая атака является однонаправленной и работает только тогда, когда порт атакующего находится в той же сети, что и Native VLAN транкового порта. Ответный трафик часто также разрешается, что дает возможность полноценного общения с изолированными устройствами. 3. 10.5.4 Сообщения DHCP (DHCP Messages) Перед изучением DHCP-атак важно вспомнить стандартный порядок обмена сообщениями (процесс DORA) между клиентом и сервером: DHCPDISCOVER: Клиент отправляет широковещательный запрос (Broadcast): "Мне нужен IP-адрес". DHCPOFFER: Сервер отвечает (Unicast): "Я сервер DHCP, могу предложить адрес 192.168.10.15, маску 255.255.255.0, шлюз 192.168.10.1 на 3 дня". DHCPREQUEST: Клиент отправляет широковещательный запрос (Broadcast): "Я принимаю это предложение". DHCPACK: Сервер подтверждает (Unicast): "Ваше принятие зафиксировано, пользуйтесь". 4. 10.5.5 Атаки на DHCP (DHCP Attacks) Существует два основных вида атак на протокол DHCP. Оба они предотвращаются внедрением технологии DHCP Snooping. Атака истощения DHCP (DHCP Starvation): Цель: Создать отказ в обслуживании (DoS) для легитимных клиентов, исчерпав весь пул свободных IP-адресов. Как работает: Используются специальные утилиты (например, Gobbler), которые генерируют множество запросов DHCPDISCOVER с поддельными MAC-адресами, пока у сервера не закончатся свободные адреса. Атака подделки DHCP (DHCP Spoofing): Цель: Подключение к сети поддельного (rogue) DHCP-сервера для выдачи неверных сетевых настроек клиентам. Возможные последствия: Неверный шлюз по умолчанию: Злоумышленник указывает адрес своего компьютера, реализуя атаку "человек посередине" (Man-in-the-Middle) для перехвата трафика. Неверный DNS-сервер: Клиентов перенаправляют на вредоносные сайты. Неверный IP-адрес: Приводит к отказу в обслуживании (DoS) для конкретного клиента. 5. 10.5.7 Атаки ARP (ARP Attacks) Суть атаки: Устройства отправляют широковещательные ARP-запросы для определения MAC-адреса по известному IP (чаще всего для поиска шлюза). Стандарт допускает отправку спонтанных ARP-ответов — так называемых gratuitous ARP (безвозмездных ARP). Уязвимость: Злоумышленник может отправить поддельный ARP-ответ с чужим IP-адресом и своим собственным MAC-адресом. Коммутаторы и хосты обновят свои ARP-таблицы ложной информацией. Инструменты: Для организации ARP Man-in-the-Middle атак используются утилиты dsniff, Cain & Abel, ettercap, Yersinia. Примечания для IPv6: В IPv6 вместо ARP используется протокол ICMPv6 Neighbor Discovery, в котором предусмотрены защитные механизмы против подделки сообщений соседей (Neighbor Advertisement spoofing). Защита: Атаки ARP-спуфинга и ARP-отравления (ARP Poisoning) предотвращаются с помощью технологии DAI (Dynamic ARP Inspection). 6. 10.5.8 Атака подделки адресов (Address Spoofing Attack) Подделка IP-адресов: Злоумышленник использует чужой валидный IP или случайный адрес. Этот вид атак сложно поддается фильтрации внутри собственной подсети. Подделка MAC-адресов (MAC Spoofing): Хакер меняет MAC-адрес своего устройства на известный MAC-адрес целевого компьютера. В сеть отправляется кадр с этим измененным MAC-адресом. Коммутатор фиксирует изменение и переписывает свою таблицу MAC-адресов (MAC Table), привязывая легитимный адрес к порту злоумышленника. В результате трафик, предназначенный для жертвы, начинает ошибочно пересылаться на порт хакера. Чтобы свитч не вернул правильную привязку обратно, атакующий запускает скрипт, постоянно генерирующий фреймы с поддельным адресом. Защита: Подделка IP и MAC-адресов минимизируется внедрением технологии IPSG (IP Source Guard). 7. 10.5.9 Атаки на протокол связующего дерева (STP Attacks) Суть атаки: Злоумышленник манипулирует протоколом STP (Spanning Tree Protocol), чтобы изменить топологию сети и перехватить весь трафик. Как работает: Атакующий рассылает фальшивые служебные сообщения BPDU (Bridge Protocol Data Units) с наивысшим приоритетом (например, с приоритетом 0). Коммутаторы воспринимают это сообщение и выбирают устройство злоумышленника в качестве корневого моста (Root Bridge). Результат: Весь трафик коммутации начинает проходить через компьютер хакера. Примечание: Подобная ситуация может возникнуть случайно, если кто-то подключит неуправляемый коммутатор без злого умысла. Защита: Такие атаки предотвращаются включением функции BPDU Guard на всех портах доступа. 8. 10.5.10 Разведка с помощью CDP (CDP Reconnaissance) О протоколе: Cisco Discovery Protocol (CDP) — прориэтарный протокол канального уровня, включенный на устройствах Cisco по умолчанию для автообнаружения соседнего оборудования и устранения неполадок. Уязвимость: CDP-сообщения отправляются в виде периодических незашифрованных мультикаст-рассылок. Они содержат IP-адрес устройства, версию ПО IOS, платформу и настройки Native VLAN. Риск: Злоумышленник, перехватив эти пакеты (например, через Wireshark), может узнать точную версию операционной системы сетевого оборудования и проверить ее на наличие специфических уязвимостей. Также возможно внедрение ложных CDP-фреймов. Методы защиты (Команды настройки): Глобальное отключение CDP на устройстве: no cdp run (включение: cdp run). Отключение CDP на конкретном интерфейсе (например, на граничных портах смотрищих наружу): no cdp enable (включение: cdp enable). Примечание: Аналогичный протокол LLDP отключается глобально командой no lldp run, а на интерфейсах — командами no lldp transmit и no lldp receive.
