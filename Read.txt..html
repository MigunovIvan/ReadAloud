Модуль 14.2: Пересылка пакетов (Packet Forwarding) Введение в тему Когда маршрутизатор (роутер) определяет лучший путь для пакета данных с помощью метода наибольшего совпадения (longest match), перед ним встает главная задача. Ему нужно понять, как именно инкапсулировать пакет (завернуть его в новый заголовку канального уровня) и куда его отправить через правильный интерфейс выхода (egress interface). 14.2.1 Процесс принятия решений при пересылке пакетов (Packet Forwarding Decision Process) Весь процесс обработки пакета маршрутизатором делится на несколько последовательных шагов: Прибытие пакета: Фрейм канального уровня с инкапсулированным внутри IP-пакетом прибывает на входящий интерфейс (ingress interface) маршрутизатора. Анализ адреса: Маршрутизатор изучает IP-адрес назначения в заголовке пакета и сверяет его со своей таблицей маршрутизации (IP routing table). Поиск совпадения: Роутер ищет наиболее специфическое совпадение (longest matching prefix) между адресом назначения и записями в таблице. Инкапсуляция и отправка: Пакет снова упаковывается в новый фрейм канального уровня и отправляется наружу через исходящий интерфейс (egress interface). Получателем может быть конечное устройство в локальной сети или следующий роутер. Сброс пакета: Если в таблице маршрутизации не найдено подходящей записи (включая маршрут по умолчанию / default route), пакет просто отбрасывается. После определения пути роутер может сделать одну из трех вещей: Переслать пакет на устройство в прямо подключенной сети: Если пункт назначения находится в той же локальной сети, роутер отправляет пакет напрямую. Чтобы узнать MAC-адрес получателя по IP, роутер использует ARP (для IPv4, отправляя ARP Request) или ICMPv6 Neighbor Discovery / NS-NA (для IPv6). Переслать пакет маршрутизатору следующего перехода (Next-Hop Router): Если сеть удаленная, пакет отправляется на следующий роутер на пути к цели. Отбросить пакет: Если совпадений нет. 14.2.2 Пересылка пакетов от конца до конца (End-to-End Packet Forwarding) Главная обязанность функции пересылки — правильно инкапсулировать пакеты в нужный тип фрейма канального уровня для каждого конкретного исходящего интерфейса (например, для Ethernet это Ethernet-фрейм, а для последовательных линий (serial links) — протоколы PPP или HDLC). Пример сквозного пути (от ПК1 к ПК2): Когда ПК1 отправляет пакет для ПК2, находящегося в другой сети, ПК1 понимает, что нужно отправить трафик на свой шлюз по умолчанию (default gateway) (например, с IP-адресом роутера R1). ПК1 проверяет свой ARP-кэш для получения MAC-адреса шлюза (если его нет, отправляет ARP-запрос). Пакет последовательно проходит через цепочку устройств (ПК1 -> Роутер R1 -> Роутер R2 -> Роутер R3 -> ПК2), причем на каждом новом участке пути содержимое и формат канального уровня (фрейм) подстраиваются под требования конкретного типа подключения. 14.2.3 Механизмы пересылки пакетов (Packet Forwarding Mechanisms) Чем эффективнее роутер справляется с инкапсуляцией, тем быстрее передаются данные. Исторически и на современных устройствах Cisco поддерживаются три механизма пересылки: Process Switching (Процессная коммутация): Устаревший метод. Каждый прибывающий пакет передается в контрольную плоскость (control plane) к центральному процессору (CPU). Процессор каждый раз вручную сверяет адрес с таблицей маршрутизации и определяет интерфейс выхода — даже если пакеты идут в рамках одного и того же потока. Работает очень медленно и в современных сетях практически не используется. Fast Switching (Быстрая коммутация): Решение промежуточного поколения. Первый пакет потока обрабатывается процессором через контрольную плоскость, но результат кэшируется, и для последующих пакетов того же потока путь берется из кэша. Cisco Express Forwarding (CEF): Самый современный и эффективный метод. Создает таблицы пересылки заранее (таблицу смежности и базу данных пересылки), оптимизируя обработку на аппаратном уровне. Простая аналогия для понимания разницы: Process switching решает математическую задачу «в столбик» каждый раз заново, даже если это абсолютно то же самое уравнение, которое вы решали секунду назад. Fast switching решает задачу «в столбик» один раз, а потом просто вспоминает готовый ответ для идентичных запросов. CEF подготавливает решения для абсолютно всех возможных задач заранее, сводя их в единую удобную таблицу (как электронную таблицу).
