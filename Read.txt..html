8.3.2 Избегание перезаписи данных. Команда cp может уничтожить существующие данные, если файл назначения уже существует. В таком случае команда cp перезаписывает содержимое существующего файла содержимым исходного файла. Чтобы проиллюстрировать эту потенциальную проблему, сначала в домашнем каталоге создается новый файл путем копирования существующего файла. Выполняется команда: cp /etc/hostname example.txt. Просмотрим информацию о файле с помощью команды ls. Выполняется команда: ls -l example.txt. Система выводит права доступа, владельца, размер файла 10 байт, дату и имя файла example.txt. Просмотрим содержимое файла с помощью команды cat. Выполняется команда: cat example.txt. Система выводит содержимое: localhost. В следующем примере команда cp уничтожает исходное содержимое файла example.txt. Выполняется команда: cp /etc/timezone example.txt. Обратите внимание, что после завершения работы команды cp размер файла изменился, а содержимое стало другим. Выполняется команда: ls -l example.txt. Теперь размер файла составляет 8 байт. Выполняется команда: cat example.txt. Система выводит новое содержимое: Etc/UTC. Чтобы защититься от случайной перезаписи, можно использовать два параметра. Первый параметр: минус i, интерактивный режим. С этим параметром команда cp запрашивает подтверждение у пользователя перед перезаписью файла. Следующий пример демонстрирует этот параметр, предварительно восстановив содержимое исходного файла. Выполняется команда: cp -i /etc/hosts example.txt. Система выводит вопрос: перезаписать файл /home/sysadmin/example.txt? Пользователь вводит ответ n, то есть нет. Если бы было введено значение y, то есть да, процесс копирования состоялся бы. Однако при запросе на перезапись файла было введено значение n, поэтому никаких изменений в файл внесено не было. Параметр минус i требует от вас вводить y или n для каждого копирования, которое может привести к перезаписи содержимого существующего файла. Это может быть утомительно, когда происходит множество перезаписей, как показано в следующем примере. Выполняется команда: cp -i /etc/skel/.* ~. Система выводит сообщения об ошибках для каталогов: параметр минус r не указан, пропускаем каталог /etc/skel/. и пропускаем каталог /etc/skel/.. (две точки). Далее система поочередно спрашивает разрешение на перезапись четырех скрытых файлов в домашнем каталоге: .bash_logout, .bashrc, .profile и .selected_editor. На каждый вопрос пользователь отвечает n. Как видно из примера выше, команда cp попыталась перезаписать четыре существующих файла, заставив пользователя ответить на четыре запроса. Если бы такая ситуация произошла для ста файлов, это очень быстро стало бы раздражать. Второй параметр: минус n. Чтобы автоматически отвечать n на каждый запрос, используйте параметр минус n. Он расшифровывается как no clobber, то есть без затирания, или без перезаписи. Выполняется команда: cp -n /etc/skel/.* ~. Система снова выводит уведомления о пропуске каталогов точка и две точки из-за отсутствия параметра минус r, но все существующие файлы пропускаются молча и автоматически, без каких-либо вопросов пользователю и без перезаписи данных.
