15.1.3. Команда статического маршрута IPv4 Общий синтаксис команды Для настройки статического маршрута для протокола IPv4 используется специальная команда глобальной конфигурации. Давайте разберем её структуру по шагам: Router(config)# ip route network-address subnet-mask { ip-address | exit-intf [ ip-address ] } [ distance ] Важное примечание: Внутри фигурных скобок вы обязательно должны указать либо IP-адрес следующего перехода (ip-address), либо исходящий интерфейс (exit-intf), либо оба эти параметра сразу. Подробный разбор каждого параметра команды Каждая часть этой команды отвечает за свой уникальный параметр настройки: network-address (Сетевой адрес): Указывает целевой IPv4-адрес удаленной сети, который вы хотите добавить в таблицу маршрутизации. subnet-mask (Маска подсети): Определяет маску подсети для удаленной сети. Полезный нюанс: Маску подсети можно изменить, чтобы объединить сразу несколько сетей в одну общую запись и создать так называемый суммарный статический маршрут. ip-address (IP-адрес следующего перехода): Указывает IPv4-адрес маршрутизатора следующего перехода (next-hop). Чаще всего применяется в сетях с широковещанием, например, в Ethernet. Обратите внимание: Использование только этого параметра может создать рекурсивный статический маршрут, когда маршрутизатору придется делать дополнительный внутренний поиск, чтобы выяснить, через какой физический порт отправлять пакет. exit-intf (Исходящий интерфейс): Указывает локальный интерфейс маршрутизатора, через который должны уходить пакеты. Создает напрямую подключенный статический маршрут. Обычно используется в конфигурациях «точка-точка» (Point-to-Point). exit-intf ip-address (Комбинация интерфейса и IP-адреса): Одновременное указание исходящего порта и IP-адреса следующего перехода. Создает полностью определенный статический маршрут, который исключает любые сомнения у оборудования. distance (Административное расстояние): Необязательный параметр, позволяющий задать значение административного расстояния в диапазоне от 1 до 255. Чаще всего используется для настройки плавающего статического маршрута (floating static route), когда ему задают расстояние выше, чем у динамических протоколов, чтобы он активировался только при падении основного канала.
