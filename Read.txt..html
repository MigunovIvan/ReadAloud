14.4.1. Источники маршрутов (Route Sources) Как роутер узнает, куда отправлять пакеты? Он создает таблицу маршрутизации, основываясь на сетях, в которых он находится. Основными источниками информации о маршрутах являются три компонента: Непосредственно подключенные сети (Directly connected networks) — сети, интерфейсы которых физически сопряжены с данным роутером. Статические маршруты (Static routes) — маршруты, которые администратор настраивает вручную. Динамические протоколы маршрутизации (Dynamic routing protocols) — протоколы (например, OSPF), с помощью которых роутеры автоматически делятся информацией друг с другом. В таблице маршрутизации источники обозначаются специальными кодами: L (Local) — локальный адрес, назначенный конкретному интерфейсу роутера. Позволяет роутеру понять, что пакет адресован именно ему, а не для пересылки дальше. Префикс для IPv4 равен /32, а для IPv6 — /128. C (Connected) — непосредственно подключенная сеть. S (Static) — статический маршрут. O (OSPF) — маршрут, динамически изученный через протокол OSPF. *** (Звездочка) — кандидат на роль маршрута по умолчанию (Gateway of last resort). 14.4.2. Принципы таблицы маршрутизации (Routing Table Principles) Существует три фундаментальных принципа работы таблиц маршрутизации: Каждый роутер принимает решение самостоятельно, основываясь исключительно на информации в своей собственной таблице. Роутер не знает, какие маршруты записаны в таблицах других устройств. Информация в таблицах разных роутеров не обязана совпадать. Наличие маршрута на роутере R1 вовсе не означает, что роутер R2 знает об этой же сети. Информация о прямом пути не гарантирует наличие обратного пути. Знание того, как переслать пакет от источника к назначению, не означает автоматического знания о том, как вернуть ответный трафик обратно. 14.4.3. Структура записей в таблице маршрутизации (Routing Table Entries) Чтобы успешно читать записи в таблицах IPv4 и IPv6, нужно понимать порядок параметров на примере динамического маршрута OSPF: Код источника (например, O). Целевая сеть (префикс и длина префикса, например, 10.0.4.0/24 или 2001:DB8:ACAD:4::/64). Административное расстояние и метрика (например, [110/50]). Следующий хоп (Next-hop) — IP-адрес следующего роутера на пути (например, via 10.0.3.2 для IPv4 или линк-локальный адрес via FE80::2:C для IPv6). Метка времени (Timestamp) — время, прошедшее с момента добавления маршрута. Исходящий интерфейс (например, Serial0/1/1). 14.4.4. Непосредственно подключенные сети (Directly Connected Networks) Прежде чем роутер сможет узнать о любых удаленных сетях, у него должен быть хотя бы один активный интерфейс с настроенными IP-адресом и маской. Как только интерфейс поднимается, роутер автоматически добавляет в таблицу маршрутизации две записи: прямое подключение (C) и локальный хост (L). Локальный маршрут (L) с префиксом /32 (IPv4) или /128 (IPv6) проверяет совпадение всех битов адреса назначения, чтобы роутер вовремя перехватил пакет, предназначенный лично ему. 14.4.5. Статические маршруты (Static Routes) Статические маршруты настраиваются администратором вручную и не обновляются автоматически при изменении топологии. Плюсы: высокая безопасность, минимальное потребление полосы пропускания и ресурсов процессора. Минусы: необходимость ручной перенастройки при изменении сети. Три главных сценария применения: Поддержание маршрутизации в небольших стабильных сетях. Организация маршрута по умолчанию (Default Route) для выхода во внешние сети. Маршрутизация трафика в тупиковые сети (Stub networks), у которых есть только один путь наружу и единственный сосед-роутер (такой роутер называется тупиковым или stub router). 14.4.6. Статические маршруты в таблице маршрутизации (Static Routes in the IP Routing Table) Команда настройки статического маршрута для IPv4: ip route [удаленная_сеть] [маска] [IP_следующего_хопа]. Команда настройки для IPv6: ipv6 route [удаленная_сеть/префикс] [IP_следующего_хопа]. В таблице маршрутизации такие записи всегда отмечены кодом S (Static). Для просмотра только статических маршрутов используется команда show ip route static или show ipv6 route static. 14.4.7. Динамические протоколы маршрутизации (Dynamic Routing Protocols) Динамические протоколы позволяют роутерам автоматически обмениваться информацией о доступности сетей и состоянии топологии. Главные преимущества — автоматический выбор лучшего пути и пересчет маршрутов при сбоях в сети. Протоколы выполняют сетевое обнаружение (network discovery), самостоятельно передавая соседям данные обо всех известных им сетях. 14.4.8. Динамические маршруты в таблице маршрутизации (Dynamic Routes in the IP Routing Table) Когда статические маршруты удаляются, а вместо них настраивается протокол OSPF, записи в таблице меняются: Код источника меняется на O (OSPF). В качестве адреса следующего хопа в IPv6 начинает использоваться линк-локальный адрес (Link-local address) соседнего роутера (начинающийся с FE80). 14.4.9. Маршрут по умолчанию (Default Route) Маршрут по умолчанию указывает роутер-шлюз, куда отправлять пакеты, если для целевого IP-адреса не нашлось более специфичной записи в таблице. В IPv4 записывается как 0.0.0.0/0, в IPv6 — как ::/0 (нулевое количество совпадений битов). Широко применяется на периферийных роутерах для перенаправления всего интернет-трафика на провайдера. Может настраиваться статически или распространяться динамически через OSPF. 14.4.10. Структура таблицы маршрутизации IPv4 (Structure of an IPv4 Routing Table) Таблица IPv4 унаследовала структуру из эпохи классовой адресации (хотя сама маршрутизация уже давно бесклассовая): Родительские маршруты (Parent routes): классовые сетевые адреса, отображаемые слева без кодов источников. Дочерние маршруты (Child routes): подсети этого класса, которые сдвинуты (отступлены) вправо. Прямо подключенные сети всегда являются дочерними подсетями, поскольку их локальные интерфейсы записываются как /32. 14.4.11. Структура таблицы маршрутизации IPv6 (Structure of an IPv6 Routing Table) Поскольку в IPv6 никогда не было классовой адресации, структура его таблицы максимально прямая и простая: Все записи выровнены и отформатированы одинаково, без разделения на родительские и дочерние подсети. Каждая запись содержит четкий источник, префикс, метрику, следующий хоп и интерфейс. 14.4.12. Административное расстояние (Administrative Distance — AD) Если роутер узнает об одном и том же сетевом адресе из двух разных источников (например, из OSPF и EIGRP), возникает вопрос: какому источнику верить? Для этого используется Административное расстояние (AD) — показатель «степени доверия» к источнику маршрута. Чем меньше AD, тем надежнее источник. Прямое подключение имеет AD = 0 (абсолютный приоритет). Статический маршрут имеет AD = 1. Внутренний EIGRP — 90. OSPF — 110. RIP — 120. Роутер всегда устанавливает в таблицу маршрутизации тот маршрут, у которого меньше административное расстояние.
