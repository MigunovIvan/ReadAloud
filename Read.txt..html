Модуль 14: Концепции маршрутизации Раздел 14.1: Определение пути (Path Determination) Этот раздел объясняет, каким именно образом маршрутизатор понимает, куда и по какому маршруту отправить пакет данных. Тема 14.1.1: Две функции маршрутизатора (Two Functions of Router) Прежде чем переслать пакет, маршрутизатор должен определить для него наилучший путь. Коммутаторы Ethernet соединяют устройства и другие коммутаторы внутри одной и той же локальной сети. Маршрутизатор соединяет между собой разные сети. У него есть несколько физических интерфейсов, и каждый из них принадлежит отдельной IP-сети. Когда маршрутизатор получает IP-пакет на один из интерфейсов, он решает, какой интерфейс использовать дальше для отправки пакета к получателю. Этот процесс называется маршрутизацией. Конечным пунктом может быть либо само целевое устройство, либо следующий маршрутизатор на пути к сети назначения. Главные функции маршрутизатора: Определить лучший путь для пересылки пакетов на основе информации из своей таблицы маршрутизации. Переслать пакеты в направлении их конечного пункта назначения. Тема 14.1.2: Пример работы маршрутизатора (Router Functions Example) Для поиска пути маршрутизатор использует таблицу IP-маршрутизации (как карту местности). Когда пакет отправляется с исходного компьютера на целевой компьютер, он проходит через маршрутизаторы (например, R1 и R2). Каждый маршрутизатор обращается к своей таблице, определяет лучший путь и передает пакет дальше, пока тот не достигнет адресата. Тема 14.1.3: Лучший путь — это самое длинное совпадение (Best Path Equals Longest Match) Что означает фраза «маршрутизатор определяет лучший путь»? Лучший путь в таблице маршрутизации также называется longest match, то есть «самое длинное совпадение». Таблица маршрутизации содержит записи с префиксом (сетевым адресом) и длиной префикса (маской подсети). Чтобы пакет соответствовал определенному маршруту, крайние левые биты в IP-адресе назначения пакета должны совпадать с битами в записи таблицы. Количество обязательных для совпадения бит задается длиной префикса. Самое длинное совпадение — это запись в таблице, у которой совпадает наибольшее количество крайних левых бит с IP-адресом назначения пакета. Маршрутизатор всегда выбирает этот вариант как приоритетный. Тема 14.1.4: Примерlongest match для IPv4 (IPv4 Address Longest Match Example) Представьте, что IPv4-пакет имеет адрес назначения 172.16.0.10. В таблице маршрутизатора есть три подходящие записи: 172.16.0.0 /12 172.16.0.0 /18 172.16.0.0 /26 Результат: запись под номером 3 (/26) имеет самую длинную маску и наибольшее количество совпадающих бит (26 бит), поэтому маршрутизатор выберет именно её для отправки пакета. Тема 14.1.5: Пример longest match для IPv6 (IPv6 Address Longest Match Example) Для IPv6 принцип работает точно так же. Если пакет направляется на адрес 2001:db8:c000::99, рассмотрим три возможных варианта в таблице: Префикс /40 — совпадает 40 бит (подходит). Префикс /48 — совпадает 48 бит (подходит и является самым длинным совпадением, выбирается маршрутизатором). Префикс /64 — требует совпадения 64 бит, но совпадают только первые 48 бит, поэтому этот вариант не подходит. Тема 14.1.6: Построение таблицы маршрутизации (Build the Routing Table) Каким образом маршрутизатор узнает о существующих сетях и заполняет свою таблицу? Основные способы: Непосредственно подключенные сети (Directly Connected Networks): Сети, которые настроены на активных интерфейсах самого маршрутизатора. Они добавляются в таблицу автоматически, как только интерфейс получает IP-адрес, маску и переходит в рабочее состояние (up and up). Удаленные сети (Remote Networks): Сети, находящиеся за пределами других маршрутизаторов (добавляются вручную статически или с помощью протоколов динамической маршрутизации). Маршрут по умолчанию (Default Route): Специальный маршрут для пересылки всех пакетов, для которых не нашлось точного совпадения в таблице (например, выход в Интернет через интернет-провайдера).
