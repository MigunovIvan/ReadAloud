Виртуальные локальные сети, или VLAN, — это группа устройств, которые взаимодействуют друг с другом так, будто они подключены к одному и тому же физическому кабелю. В основе VLAN лежат логические, а не физические соединения. Сетевые администраторы используют VLAN для сегментирования сетей по функциям, командам или приложениям. Каждая VLAN считается отдельной логической сетью. Любой порт коммутатора может принадлежать к той или иной VLAN. VLAN создает логический широковещательный домен, который может охватывать сразу несколько физических сегментов сети. Использование VLAN повышает производительность сети за счет разделения больших широковещательных доменов на более мелкие. Каждая VLAN в коммутируемой сети соответствует отдельной IP-сети, поэтому проектирование VLAN требует иерархической схемы адресации. Существуют различные типы VLAN: VLAN по умолчанию, VLAN данных, native VLAN (или родная VLAN), VLAN управления и голосовая VLAN. В среде с несколькими коммутаторами используется магистральный канал — VLAN trunk. Магистральный канал VLAN не принадлежит к какой-то одной конкретной VLAN. Это связующий канал для передачи трафика нескольких VLAN между коммутаторами и маршрутизаторами. Trunk — это соединение «точка-точка» между двумя сетевыми устройствами, которое расширяет охват VLAN на всю сеть. Когда VLAN реализованы на коммутаторе, передача одноадресного, многоадресного и широковещательного трафика от узла ограничена только теми устройствами, которые находятся в этой же VLAN. Для разделения трафика к кадрам добавляются теги. Поля тега VLAN включают тип, пользовательский приоритет, CFI и идентификатор VLAN (VID). Некоторые устройства добавляют тег VLAN даже к трафику native VLAN. Однако если порт магистрального канала 802.1Q получает кадр с тегом, идентификатор которого совпадает с native VLAN, он отбрасывает такой кадр. Для поддержки IP-телефонии требуется отдельная голосовая VLAN. К голосовому трафику можно применять политики качества обслуживания (QoS) и безопасности. Трафик голосовой VLAN должен помечаться соответствующим значением приоритета CoS на Уровне 2. Коммутаторы Cisco Catalyst поддерживают обычный и расширенный диапазоны VLAN. При настройке VLAN обычного диапазона параметры конфигурации сохраняются во энергонезависимой памяти коммутатора в файле vlan.dat. Хотя это и не обязательно, хорошей практикой считается сохранение изменений из текущей конфигурации в начальную. После создания VLAN следующим шагом является назначение портов. Существует несколько команд для определения порта как порта доступа и назначения его в VLAN. Обратите внимание: VLAN конфигурируются на порту коммутатора, а не на конечном устройстве. Порт доступа может принадлежать только одной VLAN данных одновременно. Однако он также может быть связан с голосовой VLAN. Например, порт, к которому подключены IP-телефон и ПК, будет связан с двумя VLAN: голосовой и VLAN данных. После настройки VLAN её параметры можно проверить с помощью команд show в Cisco IOS. Если порт доступа был назначен неправильно, просто повторно введите команду switchport access vlan с нужным номером VLAN. Чтобы удалить VLAN из файла vlan.dat, используется команда глобальной конфигурации no vlan с указанием номера ID. Магистральный канал — это канал 2-го уровня модели OSI. Для настройки соединяющих портов используется ряд команд, а для проверки конфигурации — команда show interfaces switchport. Чтобы удалить разрешенные VLAN или сбросить native VLAN на магистральном порту, применяются команды no switchport trunk allowed vlan и no switchport trunk native vlan. Интерфейс можно настроить в режим магистрали, режим обычного доступа или в режим согласования магистрали с соседним интерфейсом. Согласование выполняется с помощью проприетарного протокола Cisco — Dynamic Trunking Protocol (DTP), который работает по принципу «точка-точка». DTP управляетсогласованием только в том случае, если порт соседнего коммутатора настроен в режиме, поддерживающем DTP. Чтобы включить trunk на коммутаторе Cisco при подключении к устройству, не поддерживающему DTP, используются команды switchport mode trunk и switchport nonegotiate. Команда switchport mode имеет дополнительные параметры для согласования режима, включая access, dynamic auto, dynamic desirable и trunk. Для проверки текущего режима DTP используется команда show dtp interface.
