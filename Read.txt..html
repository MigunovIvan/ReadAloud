2.1.1 Эталонная топология OSPF Чтобы приступить к изучению настройки протокола OSPF, сначала разберём основу, на которой строится весь его процесс работы, — идентификатор маршрутизатора OSPF (router ID). На схеме в этом разделе представлена базовая топология сети, которая используется для настройки OSPFv2 на протяжении всего текущего модуля. На всех маршрутизаторах уже выполнена начальная базовая конфигурация, включая назначение IP-адресов на интерфейсы. Однако на данный момент на них не настроена ни статическая, ни динамическая маршрутизация. Все интерфейсы на маршрутизаторах R1, R2 и R3, за исключением интерфейса Loopback 1 на маршрутизаторе R2, находятся в магистральной области OSPF, то есть в области 0 (Area 0). Маршрутизатор провайдера (ISP) выступает в роли шлюза в интернет для всего этого домена маршрутизации. Важное примечание: в этой учебной топологии интерфейсы замыкания на себя (loopback) используются для имитации глобального подключения к интернету, а также локальных сетей, подключённых к каждому маршрутизатору. Это сделано специально для того, чтобы данную схему можно было легко воспроизвести в демонстрационных целях на реальных маршрутизаторах, у которых есть всего два физических интерфейса Gigabit Ethernet. Теперь подробно разберём устройство самой схемы. Топология состоит из трёх маршрутизаторов, объединённых в треугольник внутри области 0, при этом один из них имеет выход в интернет. В левом нижнем углу находится маршрутизатор R1. У него задействованы три интерфейса: Интерфейс Loopback 0 с IP-адресом .1 в сети 10.10.1.0/24 (имитирует локальную сеть). Интерфейс GigabitEthernet 0/0/0 с IP-адресом .5 в сети 10.1.1.4/30, который соединяет его с маршрутизатором R2 наверху. Интерфейс GigabitEthernet 0/0/1 с IP-адресом .14 в сети 10.1.1.12/30, который соединяет его с маршрутизатором R3 справа. Наверху находится маршрутизатор R2. У него задействованы четыре интерфейса: Интерфейс GigabitEthernet 0/0/0 с IP-адресом .6 в сети 10.1.1.4/30, подключённый к R1. Интерфейс GigabitEthernet 0/0/1 с IP-адресом .9 в сети 10.1.1.8/30, подключённый к R3. Интерфейс Loopback 0 с IP-адресом .1 в сети 10.10.2.0/24 (имитирует локальную сеть). Интерфейс Loopback 1 с IP-адресом .1 в сети 64.100.0.0/30, который подключён к облаку интернета справа. Интерфейс Loopback 1 и само облако интернета не входят в область 0. В правом нижнем углу находится маршрутизатор R3. У него задействованы три интерфейса: Интерфейс Loopback 0 с IP-адресом .1 в сети 10.10.3.0/24 (имитирует локальную сеть). Интерфейс GigabitEthernet 0/0/0 с IP-адресом .13 в сети 10.1.1.12/30, подключённый к R1. Интерфейс GigabitEthernet 0/0/1 с IP-адресом .10 в сети 10.1.1.8/30, подключённый к R2. 2.1.2 Режим конфигурации маршрутизатора для OSPF Протокол OSPFv2 включается с помощью команды глобальной конфигурации router ospf с указанием идентификатора процесса (process-id). Значение process-id представляет собой любое число от 1 до 65 535, которое выбирает сам сетевой администратор. Важно понимать, что идентификатор процесса имеет только локальное значение. Это значит, что на соседних маршрутизаторах OSPF не обязательно указывать одинаковое число, чтобы они смогли установить соседство друг с другом. Тем не менее хорошей практикой считается использование одного и того же номера процесса на всех маршрутизаторах OSPF в сети для удобства администрирования. После ввода команды router ospf 10 устройство переходит в режим конфигурации маршрутизатора, о чём свидетельствует изменение приглашения командной строки на R1(config-router)#. Если в этом режиме ввести знак вопроса, система отобразит список всех доступных команд. В учебном материале приведён сокращённый список, содержащий только те команды, которые понадобятся в этом модуле: area — настройка параметров области OSPF. auto-cost — расчёт стоимости интерфейса OSPF на основе его пропускной способности. default-information — управление распространением маршрута по умолчанию. distance — определение административного расстояния. exit — выход из режима конфигурации протокола маршрутизации. log-adjacency-changes — ведение журнала изменений состояния соседства. neighbor — указание соседнего маршрутизатора вручную. network — включение маршрутизации OSPF в определённой IP-сети. no — отмена команды или сброс её параметров к значениям по умолчанию. passive-interface — подавление отправки обновлений маршрутизации через указанный интерфейс. redistribute — перераспределение информации из другого протокола маршрутизации. router-id — назначение идентификатора маршрутизатора для данного процесса OSPF. 2.1.3 Идентификаторы маршрутизатора (Router ID) Идентификатор маршрутизатора OSPF (Router ID) — это 32-битное значение, которое записывается в формате обычного IPv4-адреса. Он используется для уникальной идентификации каждого маршрутизатора в сети OSPF, и абсолютно все пакеты OSPF содержат идентификатор того устройства, которое их отправило. Без идентификатора маршрутизатор не может участвовать в работе домена OSPF. Этот идентификатор может задать администратор вручную, либо маршрутизатор назначит его себе сам автоматически. Маршрутизатор с включённым OSPF использует свой Router ID для двух ключевых задач: Участие в синхронизации баз данных OSPF. На этапе обмена (состояние Exchange) маршрутизатор с самым высоким идентификатором первым отправляет свои пакеты описания базы данных (DBD). Участие в выборах выделенного маршрутизатора (DR). В многодоступных локальных сетях (например, Ethernet) маршрутизатор с самым высоким Router ID выбирается в качестве выделенного маршрутизатора (DR). Устройство со вторым по величине идентификатором становится резервным выделенным маршрутизатором (BDR). Подробно процесс этих выборов рассматривается далее в модуле. 2.1.4 Порядок приоритета выбора Router ID Маршрутизаторы Cisco определяют свой идентификатор по трём правилам, строго в следующем порядке приоритета: Явная настройка вручную. Администратор задаёт идентификатор с помощью команды router-id в режиме конфигурации OSPF. В качестве значения указывается любое 32-битное число в виде IPv4-адреса. Это самый рекомендуемый способ назначения Router ID. Адрес интерфейса Loopback. Если идентификатор не задан вручную, маршрутизатор выбирает самый высокий IPv4-адрес среди всех настроенных виртуальных интерфейсов замыкания на себя (loopback). Это второй по надёжности вариант. Адрес физического интерфейса. Если на устройстве нет ни ручной настройки, ни интерфейсов loopback, маршрутизатор выбирает самый высокий активный IPv4-адрес среди всех своих физических интерфейсов. Это наименее рекомендуемый способ, так как случайные адреса физических портов затрудняют администраторам быстрое определение конкретных устройств в сети. На блок-схеме из урока эта логика выглядит так: сначала система проверяет, задан ли Router ID явно. Если да — используется он. Если нет — проверяется наличие настроенного IPv4-интерфейса loopback. Если он есть — берётся его адрес. Если нет — выбирается самый высокий активный настроенный IPv4-адрес физического интерфейса. 2.1.5 Настройка интерфейса Loopback в качестве Router ID Вернёмся к нашей эталонной топологии. Представим ситуацию, когда на устройствах настроены и активны только физические интерфейсы, а интерфейсы loopback ещё не созданы. При включении OSPF маршрутизаторы выберут самые высокие активные IPv4-адреса своих физических портов: R1 выберет 10.1.1.14 (адрес интерфейса G0/0/1). R2 выберет 10.1.1.9 (адрес интерфейса G0/0/1). R3 выберет 10.1.1.13 (адрес интерфейса G0/0/0). Обратите внимание на важную деталь: протокол OSPF вовсе не обязан быть включён на самом интерфейсе, чтобы его IP-адрес был выбран в качестве идентификатора маршрутизатора. Достаточно того, что интерфейс настроен и находится в активном состоянии. Вместо того чтобы полагаться на физические порты, идентификатор можно привязать к интерфейсу loopback. Обычно для таких целей адресу loopback назначают 32-битную маску подсети (255.255.255.255). Это создаёт так называемый маршрут узла (host route), который не будет анонсироваться как обычная сеть другим маршрутизаторам OSPF. В примере показано, как создать такой интерфейс на R1: в режиме конфигурации интерфейса вводится команда interface Loopback 1, затем назначается адрес ip address 1.1.1.1 255.255.255.255. Если до этого момента маршрутизатор ещё не выбрал другой идентификатор и он не был задан явно, R1 примет адрес 1.1.1.1 в качестве своего Router ID. Проверить это можно командой show ip protocols | include Router ID, которая выведет строку Router ID 1.1.1.1. 2.1.6 Явная настройка Router ID На обновлённой схеме топологии показаны уже назначенные вручную идентификаторы для каждого устройства: Для R1 используется идентификатор 1.1.1.1. Для R2 используется идентификатор 2.2.2.2. Для R3 используется идентификатор 3.3.3.3. Чтобы задать идентификатор вручную, используется команда router-id в режиме конфигурации маршрутизатора OSPF. В примере для R1 сначала выполняется вход в процесс командой router ospf 10, а затем задаётся идентификатор командой router-id 1.1.1.1. После выхода из режима конфигурации проверка командой show ip protocols | include Router ID подтверждает, что устройству присвоен идентификатор 1.1.1.1. 2.1.7 Изменение Router ID После того как маршрутизатор выбрал свой идентификатор и запустил процесс OSPF, он не позволит изменить этот идентификатор на лету, пока устройство не будет перезагружено или пока не будет принудительно сброшен сам процесс OSPF. Рассмотрим пример на маршрутизаторе R1. Предположим, старый ручной идентификатор был удалён, а маршрутизатор перезагружен. При запуске он автоматически выбрал адрес своего интерфейса Loopback 0, то есть 10.10.1.1. Но нам нужно, чтобы он использовал идентификатор 1.1.1.1. Администратор заходит в режим конфигурации router ospf 10 и вводит команду router-id 1.1.1.1. Сразу после этого консоль выдаёт информационное сообщение о том, что для вступления изменений в силу необходимо перезагрузить устройство или выполнить команду clear ip ospf process. Это происходит потому, что R1 уже успел установить отношения соседства с другими маршрутизаторами под старым именем 10.10.1.1, и теперь эти соседства нужно разорвать и установить заново под новым идентификатором 1.1.1.1. Сброс процесса OSPF — это предпочтительный способ применения нового идентификатора, так как он не требует полной перезагрузки всего маршрутизатора. В привилегированном режиме вводится команда clear ip ospf process. Система спрашивает подтверждение: сбросить ли все процессы OSPF, на что нужно ответить утвердительно (ввести y). В журнале консоли сразу появляются системные сообщения: соседства с маршрутизаторами 3.3.3.3 и 2.2.2.2 переходят из состояния полной смежности (FULL) в состояние отключения (DOWN), а буквально через долю секунды устанавливаются заново и снова достигают состояния FULL. Повторная проверка командой show ip protocols | include Router ID показывает, что теперь используется новый идентификатор 1.1.1.1. 2.1.8 Проверка синтаксиса — настройка Router ID на R2 и R3 В этом интерактивном задании предлагается самостоятельно закрепить материал, настроив идентификаторы на R2 и R3. Для маршрутизатора R2, находясь в режиме глобальной конфигурации R2(config)#, необходимо выполнить три шага: Войти в режим конфигурации OSPF с идентификатором процесса 10 (команда router ospf 10). Назначить идентификатор маршрутизатора 2.2.2.2 (команда router-id 2.2.2.2). Вернуться в привилегированный режим (команда end). После этого аналогичные действия выполняются для маршрутизатора R3 с назначением идентификатора 3.3.3.3.
