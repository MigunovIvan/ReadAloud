Модуль 15: Статическая маршрутизация Тема 15.3.1: Fully Specified Static Routes (Полностью определенные статические маршруты) 1. Проблема, которую решает этот метод В предыдущих темах мы разбирали два основных типа статических маршрутов: Next-hop (указывается только IP-адрес соседа). Directly connected (указывается только собственный исходящий интерфейс). Однако в сетях с множественным доступом (например, в сетях Ethernet или Multi-Access с технологиями вроде Frame Relay/ATM в прошлом) использование только одного из этих параметров может вызывать проблемы: Если указать только интерфейс на серийной линии «точка-точка» — всё работает отлично. Но на интерфейсе Ethernet подключено множество устройств, и роутер не поймет, какому именно соседу (MAC-адресу) на этом общем сегменте отправлять пакет. Если указать только IP-адрес следующего перехода (next-hop) на сети Ethernet, роутеру приходится делать лишние итерации (рекурсивный поиск), чтобы сначала выяснить, через какой интерфейс этот адрес доступен. Решением этой проблемы является Fully Specified Static Route (полностью определенный статический маршрут), в котором жестко прописаны оба параметра одновременно. 2. Синтаксис полностью определенного статического маршрута В такой команде администратор явно указывает и исходящий интерфейс, и IP-адрес следующего перехода в одной строке: ip route [Целевая_сеть] [Маска_подсети] [Исходящий_интерфейс] [IP_адрес_следующего_перехода] Для IPv6 синтаксис аналогичен:ipv6 route [Целевая_сеть/префикс] [Исходящий_интерфейс] [IP_адрес_следующего_перехода] 3. Где и зачем это применяется на практике? Сети Ethernet (Multi-Access): Когда интерфейс смотрит в коммутатор или общую сеть, где много потенциальных соседей. Указание интерфейса и IP-адреса следующего перехода сразу дает роутеру всю необходимую информацию без задержек на рекурсивные вычисления. Отказоустойчивость и старые технологии: В некоторых специфических сценариях (например, с использованием виртуальных интерфейсов или устаревших протоколов связи) без явного указания интерфейса и шлюза одновременно таблица маршрутизации не может корректно разрешить путь. 4. Проверка и отображение в таблице маршрутизации При проверке таблицы маршрутизации (show ip route) для полностью определенного статического маршрута будут видны оба элемента: S 192.168.2.0/24 [1/0] via 172.16.2.2, GigabitEthernet 0/0/1 В строке одновременно фигурирует и шлюз (via 172.16.2.2), и конкретный физический порт (GigabitEthernet 0/0/1), через который пойдет этот трафик.
