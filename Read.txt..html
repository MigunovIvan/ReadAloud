Два точка два точка один. Синтаксис команды network. Одним из типов сетей, классифицируемых протоколом OSPF, является двухточечная сеть, или сеть типа точка-точка. Вы можете указать интерфейсы, принадлежащие такой сети, настроив команду network. Также можно настроить OSPF непосредственно на самом интерфейсе с помощью команды ip ospf, о чём речь пойдёт далее. Обе эти команды используются для определения того, какие именно интерфейсы будут участвовать в процессе маршрутизации для определённой области OSPFv2. Базовый синтаксис команды network выглядит следующим образом: В режиме конфигурации маршрутизатора вводится команда network, затем сетевой адрес, затем обратная маска или wildcard-маска, затем слово area и идентификатор области. Синтаксис с указанием сетевого адреса и обратной маски используется для включения OSPF на интерфейсах. Любые интерфейсы на маршрутизаторе, которые соответствуют сетевому адресу в команде network, получают возможность отправлять и принимать пакеты OSPF. Синтаксис с указанием области и её идентификатора относится к зоне OSPF. При настройке однообластного протокола OSPFv2 команда network должна быть настроена с одинаковым значением идентификатора области на всех маршрутизаторах. Хотя можно использовать любой идентификатор области, хорошей практикой считается использование идентификатора ноль при настройке однообластного OSPFv2. Это соглашение значительно упрощает задачу, если в будущем сеть будет расширена для поддержки многообластного OSPFv2. Два точка два точка два. Обратная маска или Wildcard-маска. Обратная маска обычно представляет собой инверсию маски подсети, настроенной на этом интерфейсе. В обычной маске подсети двоичная единица означает совпадение, а двоичный ноль означает несовпадение. В обратной маске всё обстоит с точностью до наоборот: Бит обратной маски, равный нулю, означает, что соответствующее значение бита в адресе должно совпадать. Бит обратной маски, равный единице, означает, что соответствующее значение бита в адресе игнорируется. Самый простой способ вычислить обратную маску — вычесть маску подсети из адреса 255.255.255.255. Например, для префикса двадцать четыре: из 255.255.255.255 вычитаем маску подсети 255.255.255.0 и получаем обратную маску 0.0.0.255. Другой пример, для префикса двадцать шесть: из 255.255.255.255 вычитаем маску подсети 255.255.255.192 и получаем обратную маску 0.0.0.63. Два точка два точка три. Проверка понимания — обратные маски. В этом интерактивном задании предлагается вычислить десятичную маску подсети и обратную маску, необходимые для анонсирования указанного сетевого адреса в OSPF. В качестве примера приведена сеть 10.0.0.0 с префиксом восемь. Для неё десятичная маска подсети составляет 255.0.0.0, а обратная маска будет равна 0.255.255.255. Два точка два точка четыре. Настройка OSPF с помощью команды network. В режиме конфигурации маршрутизации есть два способа определить интерфейсы, которые будут участвовать в процессе маршрутизации OSPFv2. В первом способе обратная маска определяет интерфейс на основе сетевых адресов. Любой активный интерфейс, на котором настроен IPv4-адрес, принадлежащий этой сети, будет участвовать в процессе маршрутизации OSPFv2. На примере маршрутизатора R1: сначала мы входим в режим конфигурации маршрутизатора командой router ospf 10. Затем вводим три команды network: network 10.10.1.0 0.0.0.255 area 0 network 10.1.1.4 0.0.0.3 area 0 network 10.1.1.12 0.0.0.3 area 0 Примечание: некоторые версии операционной системы Cisco IOS позволяют вводить обычную маску подсети вместо обратной маски. В таком случае система сама преобразует маску подсети в формат обратной маски. Второй способ показывает, как можно включить OSPFv2, указав точный IPv4-адрес конкретного интерфейса с использованием обратной маски из четырёх нулей. Например, ввод команды network 10.1.1.5 0.0.0.0 area 0 на маршрутизаторе R1 указывает устройству включить интерфейс GigabitEthernet 0/0/0 для процесса маршрутизации. В результате процесс OSPFv2 будет анонсировать всю сеть, к которой относится этот интерфейс, то есть сеть 10.1.1.4 с префиксом тридцать. На примере R1 это выглядит так: в режиме router ospf 10 вводятся команды: network 10.10.1.1 0.0.0.0 area 0 network 10.1.1.5 0.0.0.0 area 0 network 10.1.1.14 0.0.0.0 area 0 Преимущество точного указания интерфейса заключается в том, что вам не нужно вычислять обратную маску. Обратите внимание, что во всех случаях в качестве аргумента области указывается зона ноль. Два точка два точка пять. Проверка синтаксиса — настройка R2 и R3 с помощью команды network. Это практическое задание в тренажёре синтаксиса для анонсирования сетей, подключённых к маршрутизаторам R2 и R3. Примечание: при выполнении этого задания обратите внимание на информационные сообщения, описывающие установление смежности между маршрутизатором R1 с идентификатором 1.1.1.1 и маршрутизатором R2 с идентификатором 2.2.2.2. Схема IPv4-адресации, выбранная для идентификаторов маршрутизаторов, позволяет легко определить соседа. В самом задании для R2 требуется войти в режим конфигурации маршрутизатора OSPF с идентификатором процесса десять и настроить идентификатор маршрутизатора R2 как 2.2.2.2. Два точка два точка шесть. Настройка OSPF с помощью команды ip ospf. Вы также можете настроить OSPF непосредственно на интерфейсе вместо использования команды network. Для этого используется команда режима конфигурации интерфейса: ip ospf, затем идентификатор процесса, затем слово area и идентификатор области. Чтобы перевести маршрутизатор R1 на этот метод, сначала нужно удалить ранее введённые команды network, используя отрицательную форму с частицей no. Затем нужно зайти на каждый интерфейс и настроить команду ip ospf. Для R1 последовательность действий следующая: в режиме router ospf 10 отменяем три команды network с помощью приставки no. Затем переходим в режим конфигурации интерфейса GigabitEthernet 0/0/0 и вводим ip ospf 10 area 0. То же самое повторяем для интерфейса GigabitEthernet 0/0/1 и для интерфейса Loopback 0. Два точка два точка семь. Проверка синтаксиса — настройка R2 и R3 с помощью команды ip ospf. В этом практическом тренажёре предлагается анонсировать сети путём настройки OSPF напрямую на интерфейсах маршрутизаторов R2 и R3. На R2 команды network уже удалены, и требуется настроить маршрутизацию OSPF с идентификатором процесса десять в области ноль по очереди на интерфейсах lo0, g0/0/0 и g0/0/1. Два точка два точка восемь. Пассивный интерфейс. По умолчанию сообщения OSPF рассылаются через все интерфейсы, на которых включён этот протокол. Однако на самом деле эти сообщения нужно отправлять только через те интерфейсы, которые соединяются с другими маршрутизаторами, поддерживающими OSPF. В рассматриваемой топологии сообщения OSPFv2 отправляются через три интерфейса обратной петли или loopback-интерфейса, хотя на этих имитируемых локальных сетях нет никаких соседей OSPFv2. В реальной рабочей сети эти интерфейсы обратной петли представляли бы собой физические интерфейсы, ведущие в локальные сети с пользователями и обычным трафиком. Рассылка ненужных служебных сообщений в локальную сеть негативно влияет на неё тремя способами: Во-первых, неэффективное использование полосы пропускания. Доступная пропускная способность канала тратится на передачу ненужных сообщений. Во-вторых, неэффективное использование ресурсов. Все конечные устройства в локальной сети вынуждены принимать, обрабатывать и в итоге отбрасывать эти сообщения. В-третьих, повышенный риск безопасности. Без дополнительных настроек безопасности OSPF злоумышленники могут перехватить сообщения OSPF с помощью программ-снифферов пакетов. Обновления маршрутизации могут быть изменены и отправлены обратно на маршрутизатор, что повредит таблицу маршрутизации ложными метриками и перенаправит трафик по неправильному пути. Два точка два точка девять. Настройка пассивных интерфейсов. Используйте команду режима конфигурации маршрутизатора passive-interface, чтобы запретить передачу сообщений маршрутизации через определённый интерфейс маршрутизатора, но при этом по-прежнему разрешить анонсирование сети этого интерфейса другим маршрутизаторам. В примере конфигурации интерфейс Loopback 0 на маршрутизаторе R1 настраивается как пассивный. Примечание: интерфейс обратной петли в этом примере имитирует сеть Ethernet. В реальных рабочих сетях настраивать интерфейсы обратной петли как пассивные не требуется. Для R1 в режиме router ospf 10 вводится команда passive-interface loopback 0. Затем используется команда show ip protocols, чтобы убедиться, что интерфейс Loopback 0 отображается в списке пассивных интерфейсов. При этом в выводе команды этот интерфейс всё ещё указан в разделе маршрутизации на интерфейсах, настроенных явно для области ноль. Это означает, что его сеть по-прежнему включается в качестве записи о маршруте в обновления OSPFv2, которые отправляются маршрутизаторам R2 и R3. Два точка два точка десять. Проверка синтаксиса — настройка пассивных интерфейсов на R2 и R3. В этом задании предлагается настроить интерфейс обратной петли на R2 как пассивный. В качестве альтернативы все интерфейсы маршрутизатора можно сделать пассивными одновременно с помощью команды passive-interface default. А те интерфейсы, которые не должны быть пассивными, можно снова включить с помощью команды no passive-interface. Именно так предлагается настроить маршрутизатор R3: сначала сделать все интерфейсы пассивными по умолчанию, а затем заново включить интерфейсы GigabitEthernet. Для R2 требуется войти в режим router ospf 10, сделать пассивным интерфейс lo0, выйти в привилегированный режим и проверить настройки командой show ip protocols. Два точка два точка одиннадцать. Двухточечные сети OSPF. По умолчанию маршрутизаторы Cisco проводят выборы выделенного маршрутизатора DR и резервного выделенного маршрутизатора BDR на интерфейсах Ethernet, даже если на канале связи находится всего одно другое устройство. Вы можете убедиться в этом с помощью команды show ip ospf interface. Например, при проверке интерфейса GigabitEthernet 0/0/0 на маршрутизаторе R1 в выводе команды видно, что типом сети указан BROADCAST, то есть широковещательная сеть. Маршрутизатор R1 имеет состояние BDR, а маршрутизатор R2 является DR. Процесс выборов DR и BDR здесь совершенно не нужен, так как в двухточечной сети между R1 и R2 могут находиться только два маршрутизатора. Чтобы изменить тип сети на двухточечный и отключить процесс выборов DR и BDR, используется команда режима конфигурации интерфейса ip ospf network point-to-point на всех соответствующих интерфейсах. В примере для R1 эта команда вводится на интерфейсах GigabitEthernet 0/0/0 и GigabitEthernet 0/0/1. При вводе команды состояние соседства OSPF на несколько миллисекунд сбрасывается и устанавливается заново. После этого проверка командой show ip ospf interface показывает, что типом сети теперь является POINT_TO_POINT, а выборы DR и BDR на этом канале отсутствуют. Два точка два точка двенадцать. Интерфейсы обратной петли и двухточечные сети. Мы используем интерфейсы обратной петли, или loopback-интерфейсы, для создания дополнительных виртуальных интерфейсов для различных целей. В данном учебном случае они используются для имитации большего количества сетей, чем может физически поддерживать имеющееся оборудование. По умолчанию интерфейсы обратной петли анонсируются в OSPF как маршруты к одному узлу с префиксом тридцать два. Например, маршрутизатор R1 будет анонсировать свою сеть 10.10.1.0 с префиксом двадцать четыре маршрутизаторам R2 и R3 как отдельный хост 10.10.1.1 с префиксом тридцать два. При проверке таблицы маршрутизации на R2 командой show ip route мы увидим именно запись 10.10.1.1 с префиксом тридцать два. Чтобы имитировать реальную локальную сеть, интерфейс Loopback 0 настраивается как двухточечная сеть. Для этого в режиме конфигурации интерфейса Loopback 0 вводится команда ip ospf network point-to-point. После этого R1 начинает анонсировать полную сеть 10.10.1.0 с префиксом двадцать четыре, и в таблице маршрутизации R2 появляется более точный адрес имитируемой локальной сети. Настроить команду network на маршрутизаторе R1, используя обратную маску на основе маски подсети. Настроить команду network на маршрутизаторе R2, используя обратную маску из четырёх нулей.
