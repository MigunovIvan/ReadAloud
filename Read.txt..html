Введение в тему 10.2: Контроль доступаТема 10.2. Access Control (Контроль доступа) из курса CCNA2: Switching, Routing, and Wireless Essentials посвящена тому, как защитить сетевые устройства и ограничить к ним доступ. В предыдущих темах вы узнали, что устройства управления сетевым доступом (NAC) предоставляют AAA-сервисы. В этой теме подробно рассматривается концепция AAA и методы управления доступом.10.2.1. Аутентификация с помощью локального пароля (Authentication with a Local Password)Это самый простой, но наименее безопасный метод удаленного доступа.Как это работает: На сетевом устройстве (например, на маршрутизаторе) настраивается связка логина и пароля непосредственно для консольных портов, портов виртуальных линий (vty) или вспомогательных портов (aux).Пример команды для vty-линий:R1(config)# line vty 0 4R1(config-line)# password ci5c0R1(config-line)# loginНедостатки метода:Отсутствие отчётливости (accountability): невозможно точно узнать, кто именно зашел под общим паролем.Пароль передается в открытом виде (plaintext). Любой перехватчик трафика сможет его прочитать.Любой, кто знает пароль, получает полный доступ к устройству.Более безопасная альтернатива: Secure Shell (SSH)SSH является более защищенной формой удаленного доступа:Требует имя пользователя и пароль, которые шифруются при передаче.Учетные данные могут проверяться с помощью локальной базы данных.Обеспечивает лучшую отчетливость, так как при входе фиксируется конкретное имя пользователя.Пример настройки SSH и локальной базы:R1(config)# ip domain-name example.com R1(config)# crypto key generate rsa general-keys modulus 2048 R1(config)# username Admin secret Str0ng3rPa55w0rd R1(config)# ip ssh version 2 R1(config)# line vty 0 4 R1(config-line)# transport input ssh R1(config-line)# login localОграничения локальной базы данных:Масштабируемость: Учетные записи необходимо настраивать локально на каждом отдельном устройстве. В крупной корпоративной сети с множеством маршрутизаторов и коммутаторов это отнимает много времени.Отсутствие резервного метода: Если администратор забудет имя пользователя или пароль для конкретного устройства, единственным способом восстановления доступа останется сложная процедура восстановления пароля (password recovery).Решение: Использовать единую централизованную базу данных на выделенном сервере для всех устройств.10.2.2. Компоненты AAA (AAA Components)AAA расшифровывается как Authentication, Authorization, and Accounting (Аутентификация, Авторизация и Учет).Эту концепцию можно легко понять на примере обычной банковской кредитной карты:Authentication (Аутентификация): «Кто вы?» (Проверка личности владельца карты по ПИН-коду).*Authorization (Авторизация): «Сколько вы можете потратить?» (Определение доступного лимита и прав на покупку).Accounting (Accounting): «На что вы это потратили?» (Ведение детального учета всех совершенных транзакций).В компьютерных сетях AAA предоставляет базовый фреймворк для настройки контроля доступа:Аутентификация: определяет, кто имеет право доступа к сети.Авторизация: определяет, что именно пользователь может делать после получения доступа.*Учет (Accounting): аудирует и записывает, какие действия пользователь выполнил во время сеанса.10.2.3. Аутентификация (Authentication)Существует два основных метода реализации AAA-аутентификации: локальный и серверный.Локальная AAA-аутентификация (Local AAA Authentication):Имена пользователей и пароли хранятся локально на самом сетевом устройстве (например, на маршрутизаторе Cisco).Схема работы: Удаленный клиент подключается к маршрутизатору $\rightarrow$ запрашиваются учетные данные $\rightarrow$ маршрутизатор проверяет их по своей локальной базе данных $\rightarrow$ при успехе пользователю предоставляется доступ.Идеально подходит для небольших сетей.Серверная AAA-аутентификация (Server-Based AAA Authentication):Маршрутизатор обращается к центральному AAA-серверу, где хранятся единые базы данных пользователей для всей компании.Для связи с сервером используются протоколы RADIUS (Remote Authentication Dial-In User Service) или TACACS+ (Terminal Access Controller Access Control System).Схема работы: Клиент подключается к маршрутизатору $\rightarrow$ запрашиваются учетные данные $\rightarrow$ маршрутизатор проверяет их через удаленный AAA-сервер $\rightarrow$ доступ предоставляется на основе ответа сервера.Является оптимальным выбором при наличии большого количества сетевых устройств.10.2.4. Авторизация (Authorization)Авторизация происходит автоматически после успешного прохождения аутентификации, от пользователя не требуются дополнительные действия.Она определяет уровень прав, привилегии и ограничения пользователя в сети (что ему разрешено и запрещено делать).Процесс: После установления сеанса между маршрутизатором и AAA-сервером, маршрутизатор запрашивает у сервера разрешение на запрошенную клиентом службу. Сервер возвращает ответ со статусом PASS (разрешено) или FAIL (запрещено).10.2.5. Учет (Accounting)AAA Accounting отвечает за сбор и отчетность по использованию сетевых ресурсов (для аудита или биллинга).Собираемые данные включают: время начала и окончания сеанса, выполненные команды, объем переданных пакетов и байтов.Главная польза: В связке с аутентификацией AAA-сервер ведет детальный лог действий конкретного пользователя (все EXEC- и конфигурационные команды). Это незаменимо при устранении неполадок (troubleshooting) и расследовании инцидентов безопасности.Процесс: При успешном входе генерируется сообщение start (начало сеанса), а по завершении работы пользователя записывается сообщение stop (окончание сеанса).10.2.6. Стандарт 802.1X (802.1X)IEEE 802.1X — это стандарт протокола портовой аутентификации и контроля доступа. Он запрещает неавторизованным рабочим станциям подключаться к локальной сети через публично доступные порты коммутатора до тех пор, пока их подлинность не будет подтверждена сервером.В архитектуре 802.1X задействованы три ключевые роли:Supplicant (Суппликант / Клиент): Устройство (например, ПК или IP-телефон), которому требуется доступ к сети и которое отвечает на запросы коммутатора (работает под управлением специального 802.1X-клиентского ПО).Authenticator (Аутентификатор / Коммутатор или Точка доступа): Промежуточное устройство, контролирующее физический доступ к сети. Оно запрашивает данные у клиента, перенаправляет их на сервер аутентификации и передает клиенту решение.Authentication Server (Сервер аутентификации): Сервер (например, RADIUS), который проверяет подлинность клиента и сообщает коммутатору, разрешен ли доступ к локальной сети.
