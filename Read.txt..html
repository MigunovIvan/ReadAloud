Тема 8.4: Настройка DHCPv6 сервера (Configure DHCPv6 Server) Этот раздел курса CCNA2 полностью посвящен тому, как превратить обычный маршрутизатор Cisco IOS в сервер, клиент или ретранслятор для протокола DHCPv6. Ниже приводится подробный разбор всех подразделов, интерфейсных элементов слева и ключевых команд. 8.4.1 Роли маршрутизаторов в DHCPv6 (DHCPv6 Router Roles) В небольших сетях не нужны отдельные физические устройства под DHCPv6. Маршрутизатор Cisco IOS может выполнять три роли одновременно или по отдельности: DHCPv6 Server — предоставляет клиентам stateless (без сохранения состояния) или stateful (с сохранением состояния) конфигурацию. DHCPv6 Client — интерфейс самого маршрутизатора получает IPv6-параметры от вышестоящего сервера. DHCPv6 Relay Agent — выступает в роли ретранслятора (посредника), пересылая DHCPv6-сообщения между клиентами и сервером, если они находятся в разных сетях. 8.4.2 Настройка Stateless DHCPv6 сервера (Configure a Stateless DHCPv6 Server) При таком методе маршрутизатор рассылает базовую сетевую информацию через RA (Router Advertisement) сообщения, а за дополнительными данными (например, адресами DNS) клиент обращается к DHCPv6-серверу. Пять шагов настройки: Включение маршрутизации IPv6: Plaintext R1(config)# ipvxc unicast-routing -> ipv6 unicast-routing (Команда обязательна для генерации ICMPv6 RA сообщений) Создание имени пула DHCPv6: ipv6 dhcp pool <ИМЯ_ПУЛА> Настройка параметров в пуле: указание адресов DNS-серверов и доменного имени. Привязка пула к интерфейсу: ipv6 dhcp server <ИМЯ_ПУЛА> Проверка получения параметров хостами. 8.4.3 Настройка Stateless DHCPv6 клиента (Configure a Stateless DHCPv6 Client) Маршрутизатор может сам выступать в роли клиента, запрашивающего настройки. Шаг 1: Включить маршрутизацию командой ipv6 unicast-routing. Шаг 2–3: Настроить создание канального локального адреса (LLA) и использование SLAAC. Шаг 4–5: Проверить назначение GUA (Global Unicast Address) и получение дополнительных параметров от сервера. 8.4.4 Настройка Stateful DHCPv6 сервера (Configure a Stateful DHCPv6 Server) Stateful-режим похож на привычный DHCPv4: сервер полностью управляет выдачей IPv6-адресов клиентам. Основные отличия: В пуле DHCPv6 дополнительно задается префикс выдаваемых адресов (например, с помощью команды address prefix 2001:db8:acad:1::/64). Процедура настройки также состоит из 5 шагов (включение маршрутизации, создание пула, настройка префикса/DNS, привязка к интерфейсу, проверка). 8.4.5 Настройка Stateful DHCPv6 клиента (Configure a Stateful DHCPv6 Client) Клиентский маршрутизатор настраивается на получение полного пула адресов по протоколу DHCPv6 (Stateful). На интерфейсе, смовящем в сторону сервера, активируется запрос полной конфигурации (через флаги в RA-сообщениях Managed Address Configuration). 8.4.6 Команды проверки DHCPv6 сервера (DHCPv6 Server Verification Commands) Для контроля работы сервера используются две ключевые команды: show ipv6 dhcp pool — проверяет имя пула, параметры, выданные адреса и количество активных клиентов (Active clients). Пример вывода показывает пул IPV6-STATEFUL с двумя активными клиентами и указанным DNS 2001:4860:4860::8888. show ipv6 dhcp binding — отображает базу данных привязок выданных IPv6-адресов конкретным клиентам (их DUID и сроки аренды). 8.4.7 Настройка агента ретрансляции DHCPv6 (Configure a DHCPv6 Relay Agent) Если DHCPv6-сервер и клиенты находятся в разных подсетях, промежуточный маршрутизатор настраивается как ретранслятор (Relay Agent). Синтаксис команды на интерфейсе, смотрящем в сторону клиентов: Plaintext Router(config-if)# ipv6 dhcp relay destination <исходящий_интерфейс> (Исходящий интерфейс указывается, если в качестве адреса сервера используется канальный локальный адрес - LLA). 8.4.8 Проверка агента ретрансляции DHCPv6 (Verify the DHCPv6 Relay Agent) show ipv6 dhcp interface — подтверждает, что интерфейс переведен в режим ретрансляции (is in relay mode) и указывает целевые адреса серверов. Для проверки на стороне ОС Windows используется классическая команда ipconfig /all.
