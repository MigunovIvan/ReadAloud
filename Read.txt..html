8.3 DHCPv6 (Обзор темы) Тема 8.3 посвящена протоколу DHCPv6 (Dynamic Host Configuration Protocol for IPv6). Этот протокол используется для автоматической настройки узлов в сети IPv6 и делится на два основных режима: Stateless (без сохранения состояния) и Stateful (с сохранением состояния). Важно: Хотя DHCPv6 выполняет похожие задачи с IPv4, протоколы DHCPv4 и DHCPv6 полностью независимы друг от друга. Порты: Сервер отправляет сообщения клиенту на UDP-порт 546, а клиент отправляет сообщения серверу на UDP-порт 547. 8.3.1 Шаги работы DHCPv6 (DHCPv6 Operation Steps) Процесс взаимодействия хоста с сетью и сервером состоит из 6 последовательных шагов (особенно в stateful-режиме): Хост отправляет RS-сообщение (Router Solicitation) всем роутерам с поддержкой IPv6. Маршрутизатор отвечает RA-сообщением (Router Advertisement). Хост отправляет сообщение DHCPv6 SOLICIT, чтобы найти доступный DHCPv6-сервер. DHCPv6-сервер отвечает сообщением ADVERTISE (предложение связи). Хост отвечает DHCPv6-серверу (запрос параметров). DHCPv6-сервер отправляет REPLY-сообщение с итоговыми настройками. 8.3.2 Работа Stateless DHCPv6 (Stateless DHCPv6 Operation) В режиме Stateless DHCPv6 сервер не выдает IP-адреса и не ведет учет состояний клиентов (списков выданных адресов). Для чего нужен: Сервер передает только дополнительную информацию, которая одинакова для всех устройств в сети (например, адрес DNS-сервера). Сам глобальный уникальный IP-адрес (GUA) хост получает самостоятельно с помощью механизма SLAAC. Флаги в RA-сообщении: A = 1 — указывает клиенту использовать SLAAC для создания адреса. O = 1 (Other configuration) — говорит клиенту, что дополнительную информацию (например, DNS) можно получить у Stateless DHCPv6-сервера. M = 0 — флаг управляемого режима выключен. 8.3.3 Включение Stateless DHCPv6 на интерфейсе (Enable Stateless DHCPv6 on an Interface) Чтобы маршрутизатор рассылал RA-сообщения с правильными флагами для stateless-режима, на интерфейсе роутера вводят команду: Plaintext R1(config-if)# ipv6 nd other-config-flag Эта команда устанавливает флаг O в значение 1. Проверка конфигурации: Команда show ipv6 interface g0/0/1 | begin ND в выводе должна подтвердить: Hosts use stateless autoconfig for addresses. (Использование автоконфигурации для адресов). Hosts use DHCP to obtain other configuration. (Использование DHCP для получения прочих параметров). Отмена настройки: Для возврата к стандартному режиму без DHCP используется команда no ipv6 nd other-config-flag. 8.3.4 Работа Stateful DHCPv6 (Stateful DHCPv6 Operation) Режим Stateful DHCPv6 работает ближе всего к привычному нам DHCPv4. Для чего нужен: В этом режиме сервер полностью управляет выдачей IP-адресов и ведет учет выданных адресов (состояние клиентов). Исключение: Адрес шлюза по умолчанию (Default Gateway) хост берет не от DHCP-сервера, а из локального адреса роутера (Link-Local address из RA-сообщения). Флаги в RA-сообщении: M = 1 (Managed address configuration) — указывает хосту получать всю информацию об адресации у stateful DHCPv6-сервера. A = 0 — отключает автоматическое создание адреса через SLAAC. Примечание: Если случайно оставить флаги A = 1 и M = 1 одновременно, некоторые операционные системы (например, Windows) создадут один IP-адрес через SLAAC и получат второй адрес от DHCPv6-сервера. Поэтому на практике рекомендуется вручную переводить флаг A в значение 0. 8.3.5 Включение Stateful DHCPv6 на интерфейсе (Enable Stateful DHCPv6 on an Interface) Чтобы заставить роутер отправлять RA-сообщения для stateful-режима, применяются две команды интерфейса: Plaintext R1(config)# int g0/0/1 R1(config-if)# ipv6 nd managed-config-flag R1(config-if)# ipv6 nd prefix default no-autoconfig ipv6 nd managed-config-flag устанавливает флаг M в значение 1 (требует получения адресов от DHCP-сервера). ipv6 nd prefix default no-autoconfig устанавливает флаг A в значение 0 (отключает SLAAC). Проверка конфигурации: Команда show ipv6 interface g0/0/1 | begin ND должна показать строку: Hosts use DHCP to obtain routable addresses. (Хосты используют DHCP для получения маршрутизируемых адресов). 8.3.6 Проверка знаний (Check Your Understanding - DHCPv6) Раздел завершается итоговым тестом по теме DHCPv6: Количество вопросов: 5.
