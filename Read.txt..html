17.1 Роли и состояния портов RSTP Этот подраздел посвящен протоколу RSTP (Rapid Spanning Tree Protocol, стандарт IEEE 802.1w), который пришел на смену классическому STP (802.1D). Главное отличие RSTP — значительно более быстрая сходимость сети (свертка топологии за доли секунды вместо десятков секунд). При этом для совместимости сохранены те же принципы алгоритма и терминология. Ниже подробно разобраны все ключевые блоки материала, включая интерфейс и таблицы. 17.1.1 Сравнение STP и RSTP Хотя алгоритм определения топологии остался прежним, подход к отправке служебных сообщений и состояниям портов изменился. Основные отличия сведены в таблицу: Передача BPDU: В классическом STP корневой мош отправляет конфигурационные BPDU, а остальные коммутаторы их только ретранслируют. В RSTP каждый коммутатор каждые 2 секунды отправляет Hello BPDU самостоятельно — это работает как механизм keepalive (проверка связи). Состояния портов: STP (802.1D): Disabled, Blocking, Listening, Learning, Forwarding (5 состояний). RSTP (802.1w): Disabled, Discarding (объединяет блокировку и прослушивание), Forwarding (3 состояния). Роли портов: STP: Root, Designated, Non-Designated (блокирующий). RSTP: Root, Designated, Alternate (альтернативный, в состоянии Discarding), Backup (резервный, в состоянии Discarding). Время перехода в forwarding: В STP — до 50 секунд (с учетом таймеров). В RSTP — всего за несколько секунд (или миллисекунд для edge-портов). 17.1.2 Состояния портов RSTP В стандарте RSTP старые состояния (Blocking, Listening) объединены в одно, что упрощает логику работы: Disabled (Отключен): Порт административно выключен или не работает из-за аппаратной ошибки. Кадры не пересылаются. Discarding (Отбрасывание): Заменяет классическое состояние блокировки. Порт заблокирован для предотвращения петель, кадры не пересылаются, но коммутатор прослушивает входящие BPDU для отслеживания изменений топологии. Forwarding (Пересылка): Порт полноценно передает данные, параллельно изучая MAC-адреса устройств и обрабатывая BPDU. 17.1.3 Роли портов RSTP На каждом коммутаторе порты выполняют конкретные роли для поддержания беспетелевой топологии: Root port (Корневой порт): Порт с наименьшей стоимостью пути к корневому коммутатору (Root Bridge). Каждый коммутатор (кроме самого корневого) имеет ровно один такой порт. Через него идет трафик к корню. Designated port (Назначенный порт): Порт, который отправляет трафик от сегмента сети в сторону корневого моста. Определяется по наименьшей стоимости пути до корня. У корневого моста все порты являются назначенными. Alternate port (Альтернативный порт): Находится в состоянии Discarding и служит запасным путем к корневому мосту на случай отказа основного корневого порта. Обеспечивает мгновенную сходимость при аварии. Backup port (Резервный порт): Резерв для назначенного порта. Встречается крайне редко — только при подключении коммутатора к хабу (концентратору), когда несколько портов одного коммутатора смотрят в один сегмент. Один из них остается назначенным, а остальные уходят в Backup для предотвращения дублирования кадров. 17.1.4 Типы линий связи и краевые порты (Edge Ports) Для мгновенного перехода в режим передачи данных RSTP использует два ключевых понятия: Тип линии связи (Link Type): Point-to-Point (P2P): Полно дуплексные соединения между коммутаторами. Shared (Общие): Полудуплексные соединения (например, через хабы). Краевой порт (Edge Port): Порт доступа (Access), который смотрит на конечное устройство (ПК, сервер). Такие порты моментально переходят в состояние Forwarding, минуя этапы обучения и прослушивания. Важное правило: если на Edge-порт случайно прилетит BPDU от другого коммутатора, он мгновенно теряет статус краевого. В материале приводится пример команды show spanning-tree vlan 1 для проверки статуса на коммутаторе S3. В выводе команды отображаются: Root ID и Bridge ID: Приоритеты, MAC-адреса и таймеры. Interface Table: Таблица интерфейсов, где для каждого порта указаны его Role (Root, Desg), Sts (состояние FWD), Cost (стоимость) и Type (P2p или P2p Edge). Практические шаги выбора параметров (Алгоритм RSTP) В интерфейсе курса с пункта 17.1.5 по 17.1.9 разбирается пошаговый алгоритм того, как коммутаторы автоматически вычисляют роли в сети на основе лабораторного примера: Шаг 1: Выборы корневого моста (Root Bridge) — п. 17.1.5. Коммутаторы обмениваются BPDU. Побеждает устройство с наименьшим Bridge ID (BID), который складывается из приоритета (по умолчанию 32768) и MAC-адреса. В примере на смену приходит S1 с самым низким BID (0000.0000.1111). Шаг 2: Выбор корневых портов (Root Ports) — п. 17.1.6. Все коммутаторы, кроме корневого (S2, S3, S4), выбирают на своей стороне порт с наименьшей суммарной стоимостью пути до корневого моста S1. Шаг 3: Выбор назначенных портов (Designated Ports) — п. 17.1.7. Для каждого сегмента сети определяется порт, отвечающий за отправку трафика к корню. У корневого моста S1 абсолютно все порты — назначенные. Шаг 4: Выбор альтернативных портов (Alternate Ports) — п. 17.1.8. Если между двумя коммутаторами есть избыточные линки и оба претендуют на роль назначенных, один из них принудительно переводится в статус Alternate (альтернативный, в режиме Discarding), чтобы в сети не образовалось петли. Шаг 5: Выбор резервных портов (Backup Ports) — п. 17.1.9. Если порт смотрит в физический концентратор (хаб), где дублируется трафик, один из портов остается назначенным, а второй переводится в Backup (резервный), отсекая дубликаты кадров.
