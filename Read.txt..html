Тема 15.1.6: Исходные таблицы маршрутизации IPv4 В этом разделе анализируются начальные таблицы маршрутизации для IPv4 на примере нашего лабораторного маршрутизатора R1, пока статические маршруты еще не настроены. Главное правило исходной таблицы: По умолчанию каждый маршрутизатор знает только о тех сетях, которые к нему напрямую подключены (Directly connected). Никаких записей об удаленных сетях в таблице пока нет. Разбор вывода команды show ip route: Если посмотреть на таблицу маршрутизации роутера R1 с помощью команды show ip route, в ней отображаются следующие типы записей: Буква C (Connected — Подключено): Означает сеть, которая напрямую подключена к физическому интерфейсу маршрутизатора. В таблице R1 мы видим запись C 172.16.2.0/24 is directly connected, Serial0/1/0 — это WAN-канал связи с центральным роутером R2. И запись C 172.16.3.0/24 is directly connected, GigabitEthernet0/0/0 — это локальная сеть (LAN) роутера R1. Буква L (Local — Локальный IP-адрес): Появилась в современных версиях Cisco IOS. Она указывает конкретный IP-адрес, назначенный самому интерфейсу роутера (соответствует маске /32). Для последовательного интерфейса это L 172.16.2.1/32. Для гигабитного интерфейса локальной сети — L 172.16.3.1/32. Результаты проверки связи (Ping): Из-за отсутствия маршрутов к удаленным сетям: Роутер R1 может успешно пинговать R2, так как их разделяет всего один напрямую подключенный WAN-интервал. Но роутер R1 не может пинговать локальную сеть R3 (192.168.2.0/24), потому что в таблице нет информации о том, через какой шлюз или интерфейс отправлять туда пакеты.
