Модуль 15: Статическая маршрутизацияТема 15.6.3: Итоги модуля (What Did I Learn in This Module?)В этом финальном теоретическом блоке обобщаются все ключевые концепции статической маршрутизации для протоколов IPv4 и IPv6. Выделяются следующие основные группы тем: 1. Поддерживаемые типы статических маршрутовИ для IPv4, и для IPv6 роутеры Cisco позволяют настраивать одинаковые архитектурные виды статически определяемых путей: Standard Static Route (Стандартный статический маршрут): Используется для достижения конкретных удаленных сетей. Может задаваться через следующий переход (next-hop), через прямой интерфейс (directly connected) или в полностью определенном виде (fully specified).Default Static Route (Статический маршрут по умолчанию): Универсальное правило («маршрут последней надежды»), которое перенаправляет абсолютно весь трафик, для которого нет точных совпадений в таблице маршрутизации. В IPv4 обозначается как 0.0.0.0/0, а в IPv6 — как ::/0. Floating Static Route (Плавающий статический маршрут): Резервный маршрут, которому задается искусственно повышенное административное расстояние (Administrative Distance). Пока работает основной динамический протокол или первичный статический путь, плавающий маршрут скрыт; он активируется в таблице только при падении основного канала. Summary Static Route (Суммарный статический маршрут): Объединяет несколько смежных подсетей в одну общую сокращенную запись маршрута, что позволяет уменьшить размер таблицы маршрутизации и сэкономить ресурсы роутера.2. Главные правила и синтаксис, которые нужно помнитьАдминистративное расстояние по умолчанию: У статических маршрутов AD равна 1. Это делает их приоритетнее любых динамических протоколов (например, OSPF имеет AD = 110, EIGRP = 90), чьи маршруты роутер отбросит в пользу статики, если они ведут в ту же сеть.Особенности IPv6: При настройке статики под IPv6 на роутере обязательно должна быть включена глобальная команда ipv6 unicast-routing. Кроме того, в качестве адреса следующего перехода (next-hop) допускается использовать локальный адрес линии связи (link-local, начинающийся с fe80::), но в таком случае обязательно нужно явно указывать исходящий интерфейс (получается полностью определенный статический маршрут), так как link-local адреса уникальны только в пределах одного конкретного сегмента сети.
