7.2.1. Сервер DHCPv4 в Cisco IOSВ левом меню курса вы можете видеть структуру раздела 7.2. Первый подраздел объясняет общую концепцию.Если в сети нет отдельного выделенного сервера, маршрутизатор Cisco (Cisco IOS) можно настроить так, чтобы он сам выполнял роль DHCPv4-сервера.Такой маршрутизатор автоматически назначает и управляет IP-адресами из заранее заданных пулов для клиентов в сети.7.2.2. Шаги настройки DHCPv4 сервераНастройка состоит из трех основных шагов, которые важно выполнять последовательно:Шаг 1. Исключение IP-адресов (ip dhcp excluded-address)Маршрутизатор по умолчанию пытается раздать клиентам все адреса из созданного пула. Однако часть адресов уже должна быть закреплена за статическими устройствами (маршрутизаторы, сетевые принтеры, серверы). Их нужно исключить.Команда: Router(config)# ip dhcp excluded-address low-address [high-address]Можно исключить как один конкретный адрес, так и целый диапазон (указав нижнюю и верхнюю границы). Эту команду можно вводить несколько раз.Шаг 2. Создание имени пула (ip dhcp pool)Далее создается пул адресов и задается его уникальное имя, после чего маршрутизатор переходит в специальный режим настройки DHCP.Команда: Router(config)# ip dhcp pool pool-nameПриглашение командной строки меняется на Router(dhcp-config)#.Шаг 3. Конфигурация параметров пулаВ режиме конфигурации пула задаются основные сетевые настройки для клиентов:ЗадачаКоманда IOSЗадать диапазон сетиnetwork network-number [mask / prefix-length]Указать шлюз по умолчаниюdefault-router address [address2...address8]Указать DNS-серверdns-server address [address2...address8]Задать доменное имяdomain-name domainВремя аренды адреса (lease)`lease {days [hours [minutes]]Задать NetBIOS WINS серверnetbios-name-server address [address2...address8]7.2.3. Практический пример конфигурацииВ качестве примера рассмотрим настройку маршрутизатора R1 для локальной сети 192.168.10.0/24:PlaintextR1(config)# ip dhcp excluded-address 192.168.10.1 192.168.10.9 R1(config)# ip dhcp excluded-address 192.168.10.254 R1(config)# ip dhcp pool LAN-POOL-1 R1(dhcp-config)# network 192.168.10.0 255.255.255.0 R1(dhcp-config)# default-router 192.168.10.1 R1(dhcp-config)# dns-server 192.168.11.5 R1(dhcp-config)# domain-name example.com R1(dhcp-config)# end R1# 7.2.4 и 7.2.5. Команды проверки работоспособностиЧтобы убедиться, что сервер DHCPv4 функционирует корректно и раздает адреса, используются следующие команды из привилегированного режима (#):show running-config | section dhcp — отображает только те строки конфигурации, которые относятся к DHCP. Параметр | section фильтрует вывод.show ip dhcp binding — показывает таблицу активных привязок (какому MAC-адресу какой IPv4-адрес был выдан).show ip dhcp server statistics — выводит статистику отправленных и полученных DHCP-сообщений.Совет для ПК на Windows: Если клиентское устройство не получает адрес сразу, в командной строке Windows можно ввести ipconfig /release, а затем ipconfig /renew, чтобы принудительно запросить новые параметры у сервера.7.2.6. Интерактивный тренажер (Syntax Checker)В левом меню этому пункту соответствует интерактивное упражнение, где требуется закрепить синтаксис команды исключения адресов (например, для сети 192.168.11.0/24 исключить диапазоны .1–.9 и адрес .254).7.2.7. Отключение DHCPv4 сервераСлужба DHCP на маршрутизаторе Cisco включена по умолчанию.Чтобы полностью её отключить, используется глобальная команда: no service dhcp.Чтобы вернуть службу обратно: service dhcp.Важное примечание: Остановка или перезапуск службы может привести к временному конфликту IP-адресов в сети, если устройства попытаются использовать старые арендованные адреса.7.2.8 и 7.2.9.ретрансляция DHCP (DHCPv4 Relay / ip helper-address)Когда сервер DHCP находится в другой подсети (в крупных иерархических сетях), клиентские запросы не могут пройти дальше маршрутизатора, так как DHCP использует широковещательные сообщения (broadcast), а маршрутизаторы широковещательный трафик между подсетями не пересылают.Решение: На интерфейсе маршрутизатора, смотрящем на клиентов, настраивается специальный помощник — команда ip helper-address. Она принимает широковещательный запрос от клиента и перенаправляет его в виде адресного (unicast) пакета на конкретный IP-адрес удаленного DHCP-сервера.По умолчанию команда ip helper-address пересылает сразу 8 популярных UDP-служб, включая:Порт 37 (Time)Порт 49 (TACACS)Порт 53 (DNS)Порты 67 и 68 (DHCP / BOOTP)Порт 69 (TFTP)Порты 137 и 138 (NetBIOS)
