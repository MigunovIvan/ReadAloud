1. Введение и ручная настройка (8.1.1 IPv6 Host Configuration) Зачем нужны адреса: Для работы с IPv6 сначала нужно повторить два типа адресов: GUA (Global Unicast Address — глобальный уникальный адрес для выхода в интернет) и LLA (Link-Local Address — локальный адрес канала для связи внутри одной сети). Ручная настройка на роутере: На сетевом оборудовании GUA задается вручную с помощью команды интерфейса ipv6 address [ip-адрес]/[длина-префикса]. Ручная настройка на ПК: В операционной системе Windows (в свойствах протокола IP версии 6) также можно прописать статический IPv6-адрес и DNS-сервер вручную. Главный минус вручную: Это долго и повышает шанс совершить ошибку. Поэтому на практике большинство компьютеров настраиваются динамически (автоматически). 2. Локальные адреса канала — LLA (8.1.2 IPv6 Host Link-Local Address) Как появляется LLA: Когда на компьютере включается сетевой интерфейс, он автоматически генерирует себе адрес локального канала (Link-Local Address). Он всегда начинается с префикса fe80::. Зачем нужен LLA: Этот адрес используется устройствами для связи друг с другом в пределах только одного локального сегмента сети (даже если у них еще нет глобального IP-адреса). Почему может не быть GUA: Если в команде ipconfig вы видите только LLA (и нет глобального GUA), это значит одно из двух: либо в вашей сети нет маршрутизатора, который раздает настройки, либо компьютер еще не получил статический адрес. Важная деталь (Zone ID): Иногда операционные системы добавляют к адресу знак процента % и цифру (например, %21). Это идентификатор зоны (Zone ID), который помогает системе понять, к какому именно сетевому интерфейсу привязан этот адрес. 3. Динамическое назначение GUA: Stateless и Stateful (8.1.3 IPv6 GUA Assignment) IPv6 создавался так, чтобы избавить администраторов от рутины. Роутер постоянно рассылает сообщения RA (Router Advertisement — рекламные сообщения маршрутизатора). На их основе хост понимает, как получить свой адрес. Всего есть три основных метода динамического назначения: Метод 1: Только SLAAC (Stateless Address Autoconfiguration) Суть: Устройства сами создают себе GUA без участия сервера. Никакой сервер не ведет учет выданных адресов. Как работает: Роутер в сообщении RA передает всю необходимую информацию: сетевой префикс, длину префикса и адрес шлюза по умолчанию. Компьютер берет этот префикс и с помощью собственного MAC-адреса генерирует себе уникальный глобальный адрес. Метод 2: SLAAC вместе со Stateless DHCPv6-сервером Суть: Гибридный подход. Как работает: Компьютер получает от роутера префикс через RA-сообщение и сам создает себе GUA, но дополнительную информацию (например, адреса DNS-серверов) запрашивает у специального stateless DHCPv6-сервера. При этом сам сервер IP-адреса устройствам не выдает и не отслеживает их. Метод 3: Stateful DHCPv6-сервер (С управлением состоянием) Суть: Полный аналог классического DHCP из мира IPv4. Как работает: Роутер в RA-сообщении говорит компьютеру: «Обратись к DHCPv6-серверу за всеми настройками адреса». Компьютер идет к stateful-серверу и получает от него полный IPv6-адрес. Единственное исключение — адрес шлюза по умолчанию компьютер всё равно узнает напрямую из сообщения роутера. 4. Три управляющих флага в RA-сообщениях (8.1.4 Three RA Message Flags) Как именно компьютер понимает, какой метод использовать? Всё зависит от трех специальных флагов, которые зашифрованы в сообщении RA от роутера: Флаг A (Address Autoconfiguration): Отвечает за автоматическую настройку адреса. Если он включен, используется метод SLAAC для создания GUA. Флаг O (Other Configuration): Означает «Другая конфигурация». Говорит клиенту, что дополнительную информацию (например, DNS) можно получить у stateless DHCPv6-сервера. Флаг M (Managed Address Configuration): Означает «Управляемая конфигурация». Говорит клиенту, что нужно использовать stateful DHCPv6-сервер для получения полноценного IPv6-адреса. Комбинации флагов на практике: Только SLAAC: Флаг A = 1, флаги O = 0 и M = 0. SLAAC + Stateless DHCPv6: Флаги A = 1, O = 1 и M = 0. Stateful DHCPv6: Флаг A = 0, флаг M = 1 (флаг O в этом случае уже не важен, так как сервер и так выдает всё). 5.
